# 📄 Semantic Configuration Passport: `config/aurora/instruments.yaml` (Part 1)

> AUDIT SUMMARY
> - Document path: config/docs/Gemini/instruments_passport_gemini_v1.md
> - Scope: Lines 1-100 of `config/aurora/instruments.yaml`
> - Purpose: Capability mapping for instrument-specific precision, sizing, and execution policies.

Цей паспорт описує **можливості** та **межі впливу (Sensitivity)** конфігурацій торгових інструментів (символів). Це єдине джерело правди (SSOT) для точності розмірів та плеча.

---

## 1. Instrument Precision Constraints (`instruments.*`)

Кожен символ (напр., `BTCUSDT`, `ETHUSDT`, `SOLUSDT`) має суворі налаштування математичної точності, продиктовані контрактами біржі (LOT_SIZE та PRICE_FILTER).

- **`step_size`:** `string` (наприклад, `"0.001"` для BTC, `"1"` для DOGE).
  - *Capability:* Визначає мінімальний крок зміни кількості (Quantity).
  - *Причинність:* Використовується для математичного округлення перед відправкою ордера на біржу. Недотримання `step_size` призводить до жорсткого відхилення біржею (Fail-Closed).
- **`tick_size`:** `string` (наприклад, `"0.1"` для BTC).
  - *Capability:* Мінімальний крок зміни ціни (Price).
- **`min_qty`:** `string` (наприклад, `"0.001"`).
  - *Capability:* Абсолютний мінімальний розмір ордера в базовій валюті.
- **`min_notional`:** `string` (наприклад, `"100"` для BTC, `"5"` для альткоїнів).
  - *Capability:* Жорсткий поріг мінімальної вартості ордера в USDT. 
  - *Sensitivity:* Якщо після обчислення сайзингу розмір ордера падає нижче `min_notional`, система примусово блокує вхід (`allowed=False`), оскільки біржа відхилить такий наказ.

---

## 2. Execution Policy (`execution`)

Керує взаємодією з маржинальними механізмами біржі на рівні конкретного активу.

- **`margin_mode`:** `string` (`"isolated"`).
  - *Capability:* Перемикач режиму маржі. Використання ізольованої маржі є інваріантом захисту капіталу: ліквідація однієї позиції не впливає на баланс решти портфелю.
- **`target_leverage`:** `int` (наприклад, `25` для BTC, `10` для DOGE).
  - *Capability:* Цільове плече, яке система запитуватиме у біржі при ініціалізації інструменту.
- **`leverage_policy`:** `string` (`"set_and_verify"`).
  - *Capability:* Інструкція для адаптера. Вимагає не лише відправити команду на зміну плеча, але й дочекатися підтвердження і перевірити фактичне значення, інакше актив переводиться у стан неготовності (Fail-Fast).
- **`max_notional_utilization`:** `float` (наприклад, `0.8`).
  - *Capability:* Запобіжник перевантаження позиції. Дозволяє використовувати не більше ніж 80% від максимально допустимого notional ліміту для цього плеча на біржі.

---

## 3. Position Sizing (`sizing`)

- **`margin_pct`:** `float` (наприклад, `0.10` або `0.11`).
  - *Capability:* Скільки відсотків від загального вільного капіталу виділяється під маржу для цього конкретного активу.
  - *Sensitivity:* 🔽 Зниження обмежує ризик на один актив, але зменшує абсолютний прибуток. 🔼 Підвищення збільшує концентрацію ризику в одному інструменті (Risk Concentration).

---

## 4. Position Flipping (`flip`)

Керує здатністю системи миттєво перевертати позицію (наприклад, з LONG в SHORT).

- **`enabled`:** `bool` (`true`).
  - *Capability:* Дозволяє інтентам, які суперечать поточній відкритій позиції, ініціювати реверс (Flip), замість того щоб просто блокуватися.
- **`hysteresis_mult`:** `float` (наприклад, `1.3` для альткоїнів, `3.0` для BTC).
  - *Capability:* Мультиплікатор впевненості для перевороту. Щоб перевернути позицію, сигнал повинен бути в `N` разів сильнішим за звичайний сигнал входу.
  - *Sensitivity:* 🔼 Високий множник (як 3.0 для BTC) робить систему дуже інерційною (позиції утримуються довше, перевороти стаються рідко, зменшується кількість помилкових Flip-ів на шумі). 🔽 Низький множник збільшує агресію (часті реверси).
