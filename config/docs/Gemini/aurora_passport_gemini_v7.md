## 7. Remaining Asset Overrides (`assets`)

Блок з 601 по 1081 рядок містить масивні оптимізаційні профілі (Asset Profiles) для решти активів системи.

### `DOGEUSDT`
- **Capability:** Конфігурація для високоризикового альткоїна. 
- **Sensitivity:** Характеризується високим левериджем (якщо дозволено біржею) та специфічними вагами, які зазвичай сильно покладаються на `volume_spike` та `tfi` (через залежність від новинного фону). *Примітка: У `strategies.yaml` наразі цей актив закоментовано (вимкнено).*

### `XRPUSDT`
- **Capability:** Конфігурація для активу з частими періодами консолідації.
- **Sensitivity:** Має унікальні `regime_thresholds`, що дозволяють стратегії агресивніше збирати прибуток під час боковиків (`FLAT` / `MEAN_REVERSION`). Згідно зі `strategies.yaml`, працює в гібридному режимі (конкурує за пріоритет з `md_amr`).

### `BNBUSDT`
- **Capability:** Біржовий токен Binance.
- **Sensitivity:** Зазвичай має меншу волатильність і вимагає консервативніших `sl_pct` (стоп-лосів), оскільки рухи більш плавні.

### `__default__`
- **Capability:** Fallback-конфігурація (Профіль за замовчуванням).
- **Причинність:** Якщо архітектор додасть новий актив (наприклад, `ADAUSDT`) у систему через `instruments.yaml` та `strategies.yaml`, але забуде прописати для нього унікальні альфа-ваги тут, стратегія `aurora` не впаде (Fail-Safe). Вона використає цей `__default__` блок, який містить максимально збалансовані (консервативні) ваги та широкі стоп-лоси, що підходять для середньостатистичного інструмента.
