# **ДЕТАЛЬНА АНАЛІЗ ПОТОЧНИХ ПРОБЛЕМ**

## **Problem #1: Risk Manager Blocking 95% of Orders**

###症狀 у логах:
```json
{
  "event_type": "ORDER_REJECTED",
  "why": "Trading not allowed by risk manager",
  "risk_score": 0.876881109587653,
  "is_trading_allowed": false
}
```

### Root Cause Analysis:
Формула risk_score = (kelly_fraction * kelly_weight) + (cvar_limit * cvar_weight) + ... дає результат 0.85+
Порог is_trading_allowed: risk_score > 0.9 → FALSE

### Рішення:
1. Розробити test signal з відомим risk_score
2. Додати explicit logging кожного компонента risk_score
3. Переглянути vфункцію `_calculate_risk_parameters()` в risk_management.py
4. Можливо, порог повинен бути 0.95 або масштабування неправильне

## **Problem #2: Exposure Limit Exceeded (Double-Booking)**

###症狀 у логах:
```json
{
  "event_type": "ORDER_REJECTED",
  "why": "Exposure limit exceeded: 3281.11 > 1497.55",
  "portfolio_limit": 1497.54759176,
  "new_total": 3281.113818
}
```

### Root Cause:
1. ORDER_INTENT → exposure_guard.reserve() ✅ (299.07 USD)
2. ORDER_REJECTED (risk gate) → но exposure НЕ released ❌
3. ORDER_INTENT #2 → exposure_guard.reserve() ✅ (297.43 USD)
4. Сума: 299.07 + 297.43 = 596.5, but наступний орден спробує додати ще 299 → перевищення

### Рішення:
```python
# У fsm.py, коли handle() повертає REJECT
def handle(self, msg):
    result = open_flow.handle(msg)
    if result and result.op == "ERR":
        # Release exposure reservation
        reserve_key = msg.pld.get("idempotent_key") or msg.rid
        self.exposure_guard.release(reserve_key)  # ADD THIS
    return result
```
