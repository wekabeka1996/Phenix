## Завдання для LLM Агента: Реалізація Захисту від Ліквідації

**RID:** `AURORA_LIQUIDATION_GUARD_V1`
**Мета:** Додати механізм розрахунку **приблизної ціни ліквідації** для позицій, що відкриваються, та впровадити запобіжник, який відхилятиме торгові наміри, якщо ціна входу занадто близька до розрахованої ціни ліквідації.

**Кроки:**

1.  **Дослідити/Підтвердити Формулу Ціни Ліквідації (Binance USDⓈ-M Futures):**

Ймовірно, вона залежатиме від: ціни входу (`entry_price`), плеча (`leverage`), кількості (`quantity`), балансу гаманця (`wallet_balance`), сумарної підтримуючої маржі для інших позицій (`total_maintenance_margin`), та ставки підтримуючої маржі (`maintenance_margin_rate`) для даного розміру позиції.

            * Якщо будь-яка з перевірок не проходить, логуй `ERROR` "Order book sequence gap detected" (включи `symbol`, `event['U']`, `event['u']`, `self.last_final_update_id[symbol]`) та **ініціюй ресинхронізацію** (напр., емітуй спеціальну подію `CMD:RESYNC_ORDERBOOK` або виклич метод адаптера для запиту REST snapshot).

    * **Дія:**
        * **При Записі (`append`):**

Твоя ідея **додати гранулярне логування** — зберігати основний лог, але паралельно записувати ключові події та рішення кожного домену в окремі файли — є чудовим рішенням для покращення спостережуваності та спрощення налагодження. 👍
