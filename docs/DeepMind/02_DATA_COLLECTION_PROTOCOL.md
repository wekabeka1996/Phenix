# Інструкція з Експлуатації: Збір Даних та Навчання Neocortex

Цей документ визначає правила роботи з системою Aurora/Phenix у період збору даних (Data Gathering Phase) для підготовки до навчання складних ШІ-моделей (Offline RL, VAE).

---

## 1. Які логи НІКОЛИ не можна видаляти (Золотий Фонд)

Ваша архітектура побудована на Offline-навчанні. Якщо ви видалите історію — ШІ ніколи не порозумнішає. Наступні файли повинні бекапитися (архівуватися) як зіниця ока:

1. **`logs/shadow_telemetry/decision_ledger_v1.jsonl`** 
   - *Що це:* Головний журнал для ШІ. Містить стан ринку ($S_t$), думку моделі ($A_t$) та результат угоди ($R_t$). Це ідеальний датасет для CQL/IQL.
2. **`logs/order_log_v1.jsonl`** 
   - *Що це:* Оригінальні наміри FSM. Потрібен для реконструкції контрфактуалів (Що було б, якби...).
3. **`logs/aurora_core.log`** 
   - *Що це:* Базовий журнал виконання та стресу (включає `EXECUTION_GUARD_BLOCKED`). Необхідний для формування штрафів у функції винагороди (Reward).
4. **`logs/features/alpha_input_v1.jsonl`**
   - *Що це:* Безперервний потік фічів та скорингу від `alpha_search`. Необхідний для Unsupervised-навчання автоенкодера (VAE), оскільки VAE вчиться "розуміти світ" на мільйонах рядків, навіть якщо угод не було.

## 2. Як система має працювати зараз (Shadow Production)

1. **Запуск:** Запускайте систему у звичайному режимі (як ви це робите завжди для торгівлі на live/testnet).
2. **Інваріант Безпеки:** Упевніться, що в конфігах (`domains.yaml` або `facade.py`) встановлено **`neocortex_enforcement_mode: "shadow"`**. Це гарантує, що `BaselineController` лише збирає дані і тренується в тіні, але не блокує ваші угоди.
3. **Що збирати:** Просто дайте системі торгувати. Вона автоматично наповнюватиме `decision_ledger_v1.jsonl` правильними, каузальними рядками при кожному `EVT:TRADE_EXECUTED` або `DECISION_BLOCKED`.

## 3. Відповіді на критичні експлуатаційні питання

### Питання 1: Чи вплинуть розриви в роботі (наприклад, система вимкнена на 12 годин) на якість даних?
**Відповідь: НІ, система розроблена так, щоб витримувати розриви.**
- Наш `NeocortexStateAggregator` працює як "Чиста функція" (Stateless-per-event). Він не зберігає нескінченну пам'ять, а формує вектор стану ($S_t$) виключно з поточних фічів. 
- Математична властивість Маркова (Markov Property) зберігається: стан $S_t$ у момент включення системи достатньо описує ринок для прийняття рішення $A_t$. 
- **Єдиний мінус перерв:** Ви втрачаєте історичні семпли для навчання VAE (модель не побачить, як поводився ринок під час вашого сну). Але це впливає лише на *кількість* даних, а не на їхню каузальну *чистоту*. Вимикати систему безпечно.

### Питання 2: Чи підійдуть дані з класичних Бектестів для навчання ШІ?
**Відповідь: ЧАСТКОВО (Підходять як "Срібло", але не як "Золото").**
- **Чому ТАК:** Бектести (`AuroraSimEnv` або `judge_simulator`) можуть швидко згенерувати мільйони рядків для `alpha_input_v1.jsonl`. Цих даних достатньо, щоб "прогріти" VAE (навчити його стискати фічі в Латентний простір).
- **Чому НІ:** Бектести рідко ідеально симулюють мікроструктуру (проковзування/Slippage, мережеві затримки/Latency, відхилення біржі/Exchange Rejects). `decision_ledger_v1.jsonl`, отриманий у *Live Shadow Mode*, містить реальну ціну виконання (Realized PnL), а не теоретичну. Для тренування Offline RL (щоб ШІ навчився боятися токсичних маркет-умов) вам потрібні саме **живі (Live) або Тіньові (Shadow)** дані. Бектести — для VAE, Живі логи — для PPO/CQL.

### Питання 3: Чи можна переналаштовувати або видаляти базу `*.db` (наприклад, `order_ledger.db`)?
**Відповідь: ТАК, можна (з обережністю).**
- База `data/order_ledger.db` належить домену `execution_position` (FSM). Вона використовується для ідемпотентності ордерів та захисту від подвійних заповнень (Double Fills) після крашу системи. 
- Якщо ви зміните її або видалите (за умови відсутності відкритих позицій), FSM просто почне роботу з чистого аркуша. 
- **Головне:** `order_ledger.db` **НЕ Є** джерелом правди для навчання ШІ. Навчання ШІ спирається виключно на незмінні текстові журнали у форматі `.jsonl` (описані в Розділі 1). Тому маніпуляції з SQLite базою жодним чином не "отруять" мозок вашого майбутнього Неокортексу.
