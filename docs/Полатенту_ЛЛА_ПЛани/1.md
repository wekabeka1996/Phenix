## 1. High-Level Concept: Latent-Life Architecture (LLA)

The system represents a paradigm shift in algorithmic trading, moving away from heuristic signal processing towards **Latent-Life Architecture (LLA)**. Unlike traditional bots that operate on raw market data (price, volume, indicators), this system operates on a compressed, semantic representation of the market state — the **Latent Manifold ($z$)**.

### Core Pillars of Revolutionarity:

1.  **Latent Space Navigation:**
    Instead of trading discrete price levels, the agent perceives the market as a continuous trajectory within a low-dimensional latent space derived via **Variational Autoencoders (VAE)**. This filters high-frequency noise and extracts the underlying "physics" of market regimes.

2.  **Separation of Perception and Action:**
    *   **Perception (BrainCore):** A dedicated subsystem responsible for "understanding" the market (Unsupervised Learning via VAE and World Models). It predicts future states ($z_{t+1}$) regardless of trading intent.
    *   **Action (PPO Policy):** A Reinforcement Learning agent that acts upon the latent state representation provided by the Perception layer.

3.  **Geometric Risk Awareness (Concept):**
    The system treats risk not just as a statistical metric (drawdown), but as a geometric barrier in the latent space. Future implementations utilize the **Geometric Schrödinger Bridge (GSB)** concept to find optimal trajectories between current states and target profitability zones while avoiding "forbidden" high-risk manifolds.

4.  **Shadow-First Evolution:**
    The system implements a biological-inspired lifecycle: *Observer (R0)* $\to$ *Learner (R1)* $\to$ *Advisor (R2)* $\to$ *Agent (R3)*. This guarantees safety by validating the agent's internal model against reality in a zero-risk "Shadow Mode" before granting actuation privileges.

## 2. Global Architecture Description

The system follows a **Hybrid Event-Driven Architecture** combining low-latency AsyncIO processing with isolated Multiprocessing for heavy compute tasks. It adheres to **Domain-Driven Design (DDD)** principles, orchestrated by the `vFoundation` framework.

### 2.1. Structural Pattern: Sidecar & Kernel
The architecture is divided into two primary process groups to ensure the "Trade Execution Critical Path" is never blocked by ML inference.

*   **Aurora Kernel (The Body):**
    The monolithic execution engine responsible for connectivity, feature engineering, and order management. It operates on a high-frequency event loop. It acts as the "Body" that senses the world and executes actions.

*   **Neocortex Domain (The Brain):**
    A completely isolated domain (Sidecar pattern) that consumes telemetry from the Kernel. It performs heavy cognitive loads (training, inference, graph building) asynchronously.

### 2.2. Component Interaction
The system utilizes a dual-layer communication protocol:
1.  **Hot Path (In-Memory/IPC):** `vFoundation` Event Bus (`FSMCore`) for real-time signaling.
2.  **Audit Path (WAL - Write Ahead Log):** Immutable, append-only JSONL logs (`ops/wal`, `logs/features`) serve as the Single Source of Truth (SSOT) for data ingestion and offline training.

### 2.3. The BrainBridge
To overcome the Python GIL (Global Interpreter Lock), the Neocortex implements a **Bridge Pattern**:
*   **Main Process:** Handles I/O, parsing, and buffer management.
*   **Worker Process (Spawned):** Hosts the PyTorch runtime (`BrainCore`). Data is serialized (Pickled) and passed via IPC pipes, ensuring zero impact on the ingestion latency.

## 3. Tech Stack & Environment

### Core Runtime
*   **Language:** Python 3.10+ (Strict Type Hinting).
*   **Framework:** `vFoundation` (Custom FSM & Event Bus implementation).
*   **Concurrency:** `asyncio` (uvloop compatible) for I/O; `multiprocessing` (spawn context) for ML.

### Data & Configuration
*   **Configuration:** **Pydantic V2**. Strict schema validation, `extra='forbid'`, no implicit defaults. YAML serves as the configuration SSOT.
*   **Serialization:** JSONL (primary data transport), Pickle (IPC).
*   **Storage:**
    *   **Hot:** In-Memory Ring Buffers (`EpisodicBuffer`).
    *   **Warm:** SQLite (Planned for Metadata/Causal Graph).
    *   **Cold:** File System (`logs/`, `checkpoints/`).

### Machine Learning (The Cortex)
*   **Engine:** **PyTorch**.
*   **Architectures:**
    *   **VAE (Variational Autoencoder):** For state compression ($x \to z$).
    *   **GRU/LSTM (World Model):** For dynamics prediction ($z_t \to z_{t+1}$).
    *   **PPO (Proximal Policy Optimization):** For decision making ($\pi(a|z)$).
*   **Math:** `NumPy` for vectorization, `SciPy` for signal processing.

## 4. Data Flow Pipeline

The data lifecycle follows a strict **Perception-Cognition-Memory** loop.

### Step 1: Perception (Ingestion)
*   **Source:** The `MultiTailer` component monitors three asynchronous streams:
    1.  **Feature Stream:** `logs/features/*.log` (Market Exteroception: OBI, Volatility, Price Delta).
    2.  **Intent Stream:** `logs/order_log_v1.jsonl` (Agent Actions: ORDER_PLACED).
    3.  **Outcome Stream:** `logs/aurora_core.log` (Environment Feedback: PnL, Fills).
*   **Normalization:** Raw JSON/Text data is parsed, validated against schemas, and normalized into strict `float32` vectors (`MarketObservation`).

### Step 2: Cognition (Fast Path - Amygdala)
*   The `MarketObservation` passes through the **Amygdala** (Valuation Engine).
*   **Valuation:** The system calculates an `importance_score` ($imp_t$) based on reward magnitude (PnL) and surprise (Prediction Error). This determines *if* the data is worth remembering.

### Step 3: Cognition (Slow Path - BrainCore)
*   **Bridge Crossing:** The observation is batched and sent across the process boundary to the Worker Process.
*   **Encoding:** The VAE encodes the high-dimensional feature vector ($x \in \mathbb{R}^{15}$) into a stochastic latent vector ($z \in \mathbb{R}^{16}$).
*   **Inference:**
    *   The **World Model** predicts the next state $\hat{z}_{t+1}$.
    *   (R2+) The **PPO Policy** outputs a distribution over actions $\pi(a|z)$.

### Step 4: Memory (Consolidation)
*   **Short-Term:** The tuple $(z_t, a_t, r_t, z_{t+1})$ is stored in the `EpisodicBuffer` (RAM).
*   **Learning:** Periodically, batches are sampled from the buffer to update the VAE and World Model weights via Backpropagation.
*   **Persistence:** Model weights are checkpointed to disk (`data/checkpoints/`) to ensure knowledge survival across restarts.

### Step 5: Feedback (Shadow Loop)
*   The system emits `EVT:NEOCORTEX_SHADOW_INTENT` containing the agent's proposed action and confidence level.
*   This event is logged for **Divergence Analysis** (comparing Neocortex intent vs. Legacy Aurora execution).
