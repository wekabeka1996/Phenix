# MD-AMR Minimal Corrective Patch — Strategy-Aware CMD:PROCESS_STRATEGY Warmup Gating

## Defect Summary
The `FeatureEngineering` module currently enforces a monolithic, global `full_ready` gate with `enforcement_mode=fail_fast`. This rejects `CMD:PROCESS_STRATEGY` for symbols missing deep Aurora readiness arrays (like `macro_resid`), effectively silencing lightweight strategies like `md_amr` that only need 96 basis_bars to operate.

## Chosen Repair Shape: Option B (Degraded-but-Emittable Strategy Trigger Contract)
We will introduce a strategy-aware mechanism allowing `FeatureEngineering` to emit `CMD:PROCESS_STRATEGY` with `warmup.full_ready=False` specifically for symbols assigned to strategies that opt-in to degraded payloads. Downstream handlers (or the StrategyGateway) will decide whether to proceed.

### Proofs for Option B safety:
1. **Does not blur ownership**: `FeatureEngineering` keeps ownership of computing `full_ready` structurally (evaluating features) and emitting triggers. `DecisionMaking` handlers/gateways own the business truth of whether `full_ready=False` blocks a trade.
2. **Does not silently weaken Aurora**: The `AuroraHandler` processes signals through `StrategyGateway`, which strictly evaluates its own `_warmup_gate_before_trade_intent` checking `fe_warmup_dict["full_ready"]`. Any attempt by Aurora to execute a trade on degraded metadata will be blocked at the gateway cleanly.
3. **Degraded payload is contract-safe**: FeatureEngineering already fail-closes missing features (e.g. `features["macro_resid"] = None`). Downstream handlers must check metadata existence anyway.
