# Домен Feature Engineering (Інженерія Особливостей)

## Загальна інформація

**Ідентифікатор домену:** `feature_engineering`  
**Роль в системі:** Розрахунок технічних індикаторів та особливостей ринку

## Архітектурна роль

Домен `feature_engineering` є математичним ядром аналітичної частини системи Aurora. Він перетворює сирі ринкові дані в структуровані технічні індикатори, які використовуються для прийняття торгових рішень.

### Відповідальність
- Розрахунок Order Book Imbalance (OBI)
- Обчислення Trade Flow Imbalance (TFI)
- Визначення зміни ціни (delta_price)
- Перетворення ринкових даних в аналітичні сигнали

## Структура домену

### Основні компоненти

#### FeatureEngineering
Головний клас домену, що реалізує розрахунок технічних індикаторів.

**Ініціалізація:**
- Підписка на події `EVT:MARKET_TICK_RECEIVED`
- Ініціалізація сховища останніх tick даних
- Налаштування логування

**Методи життєвого циклу:**
- `start()` - запуск компоненту
- `stop()` - зупинка компоненту

### Внутрішня архітектура

#### Цикл обробки
```
on_market_tick() -> _calculate_and_emit_features()
    ├── Отримання поточних та попередніх tick даних
    ├── Розрахунок OBI (Order Book Imbalance)
    ├── Розрахунок TFI (Trade Flow Imbalance)
    ├── Розрахунок delta_price
    └── Емісія EVT:FEATURES_CALCULATED
```

#### Кешування даних
- Збереження останніх tick даних для кожного символу
- Порівняння поточних та попередніх значень
- Автоматичне оновлення при отриманні нових даних

## FSM події

### Генеровані події

#### EVT:FEATURES_CALCULATED
**Частота:** При отриманні кожного нового MARKET_TICK_RECEIVED  
**Направлення:** Decision Making, Risk Management, Regime Detector  

**Payload структура:**
```json
{
  "ts": 1640995200000,
  "symbol": "BTCUSDT",
  "features": {
    "obi": "0.15",
    "tfi": "-0.05",
    "delta_price": "25.50",
    "absorption": "0.0",
    "price": "50000.00"
  }
}
```

**Опис:** Передає розраховані технічні індикатори для прийняття рішень.

### Споживані події

#### EVT:MARKET_TICK_RECEIVED
**Джерело:** Market Data  
**Використання:** Отримання сирих ринкових даних для розрахунку індикаторів  
**Частота:** Реального часу (5 сек на символ)

## Взаємодія з іншими доменами

### Синхронні зв'язки

#### Decision Making
- **Вхід:** EVT:FEATURES_CALCULATED
- **Використання:** Використання індикаторів для оцінки торгових сигналів
- **Частота:** Реального часу

#### Risk Management
- **Вхід:** EVT:FEATURES_CALCULATED
- **Використання:** Аналіз волатильності через delta_price та imbalance метрики
- **Частота:** Реального часу

#### Regime Detector
- **Вхід:** EVT:FEATURES_CALCULATED
- **Використання:** Визначення ринкового режиму на основі індикаторів
- **Частота:** Реального часу

### Асинхронні залежності
Залежить від Market Data для отримання сирих даних.

## Розрахунок індикаторів

### Order Book Imbalance (OBI)
```
OBI = (bid_size - ask_size) / (bid_size + ask_size)
```
**Діапазон:** [-1, 1]  
**Інтерпретація:** Позитивне значення вказує на більший bid volume, негативне - на більший ask volume.

### Trade Flow Imbalance (TFI)
```
TFI = (buy_volume - sell_volume) / (buy_volume + sell_volume)
```
**Діапазон:** [-1, 1]  
**Інтерпретація:** Позитивне значення вказує на переважання покупок, негативне - продажів.

### Delta Price
```
delta_price = current_price - previous_price
```
**Інтерпретація:** Зміна ціни між ticks. Обмежено 1000ms для уникнення великих стрибків.

## Конфігурація

### Основні параметри
```yaml
domain_configuration:
  feature_engineering:
    trading_mode: "live"  # Зазвичай live для отримання реальних даних
```

### Режими роботи
- **live:** Обробка бойових ринкових даних
- **testnet:** Обробка тестових ринкових даних

## Моніторинг та діагностика

### Логування
- **Інформаційні повідомлення:** Запуск/зупинка компоненту
- **Помилки:** Проблеми з розрахунком індикаторів, невалідні дані

### Метрики
- Кількість оброблених tick'ів
- Частота розрахунку індикаторів
- Помилки розрахунків

## Обробка помилок

### Стратегії відновлення
1. **Невалідні дані:** Пропуск проблемних tick'ів з логуванням
2. **Ділення на нуль:** Перевірка denominator перед розрахунком
3. **Exception handling:** Логування помилок без зупинки обробки

### Graceful degradation
При проблемах з окремими розрахунками продовжує обробку інших індикаторів.

## Тестування

### Інтеграційні тести
- Валідація коректності розрахунку всіх індикаторів
- Перевірка обробки edge cases (нульові об'єми, ціни)
- Тестування емісії подій з правильним payload

### Модульні тести
- Перевірка математичних формул OBI/TFI
- Валідація діапазонів значень
- Тестування обробки невалідних вхідних даних

## Розширення

### Майбутні індикатори
- **Absorption:** Міра поглинання ліквідності
- **Volatility measures:** Додаткові метрики волатильності
- **Higher timeframe features:** Індикатори на більших таймфреймах
