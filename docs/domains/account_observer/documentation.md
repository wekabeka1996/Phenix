# Домен Account Observer (Спостерігач Рахунку)

## Загальна інформація

**Ідентифікатор домену:** `account_observer`  
**Роль в системі:** Моніторинг виконаних угод та емісія подій про трейди

## Архітектурна роль

Домен `account_observer` виконує функцію пасивного моніторингу торгової активності на біржі. Він періодично опитує API біржі для отримання інформації про останні виконані угоди та перетворює їх в стандартизовані події FSM системи.

### Відповідальність
- Моніторинг нових трейдів через read-only API
- Відстеження ID трейдів для уникнення дублікатів
- Перетворення сирих даних трейдів в структуровані події
- Забезпечення системи актуальною інформацією про виконані операції

## Структура домену

### Основні компоненти

#### AccountObserver
Головний клас домену, що реалізує моніторинг трейдів.

**Ініціалізація:**
- Налаштування Binance Client на основі `trading_mode`
- Вибір API ключів залежно від режиму роботи
- Налаштування списку символів для моніторингу
- Конфігурація інтервалу опитування

**Методи життєвого циклу:**
- `start()` - запуск фонового опитування
- `stop()` - зупинка моніторингу

### Внутрішня архітектура

#### Цикл опитування
```
_poll_loop() -> _poll_trades()
    ├── Опитування кожного символу з конфігурації
    ├── Отримання останніх трейдів (get_my_trades)
    ├── Фільтрація нових трейдів
    └── Емісія подій EVT:TRADE_EXECUTED
```

#### Управління дублікатами
- Відстеження оброблених trade_id в Set
- Пропуск вже оброблених трейдів
- Автоматичне очищення при перезапуску

## FSM події

### Генеровані події

#### EVT:TRADE_EXECUTED
**Частота:** При виявленні нових трейдів (зазвичай кожні 5 секунд опитування)  
**Направлення:** Position Tracking, Risk Management, Audit Trail  

**Payload структура:**
```json
{
  "symbol": "BTCUSDT",
  "side": "buy",
  "price": "50000.00",
  "quantity": "0.001",
  "ts": 1640995200000,
  "fees": "0.0001",
  "venue": "binance"
}
```

**Опис:** Повідомляє систему про виконання нової торгової операції.

### Споживані події
Домен не споживає зовнішні події - працює автономно.

## Взаємодія з іншими доменами

### Синхронні зв'язки

#### Position Tracking
- **Вхід:** EVT:TRADE_EXECUTED
- **Використання:** Оновлення стану позицій на основі реальних трейдів
- **Частота:** Подієво (при нових трейдах)

#### Risk Management
- **Вхід:** EVT:TRADE_EXECUTED
- **Використання:** Перерахунок ризиків після виконання операцій
- **Частота:** Подієво (при нових трейдах)

#### Audit Trail
- **Вхід:** EVT:TRADE_EXECUTED
- **Використання:** Запис операцій в аудит лог
- **Частота:** Подієво (при всіх трейдах)

### Асинхронні залежності
Домен працює незалежно, але його дані критичні для коректного відстеження позицій.

## Конфігурація

### Основні параметри
```yaml
trading_mode: "hybrid_live_data_testnet_exec"

binance_api:
  testnet:
    api_key: "${BINANCE_TESTNET_API_KEY}"
    api_secret: "${BINANCE_TESTNET_API_SECRET}"

account_observer:
  poll_interval: 5          # Інтервал опитування в секундах
  symbols:                  # Список символів для моніторингу
    - BTCUSDT
    - ETHUSDT
    - BNBUSDT
  trade_limit: 50          # Кількість останніх трейдів для перевірки
```

### Режими роботи
- **live:** Моніторинг бойових трейдів
- **testnet:** Моніторинг тестових трейдів
- **hybrid:** Автоматичний вибір залежно від конфігурації

## Моніторинг та діагностика

### Логування
- **Інформаційні повідомлення:** Виявлення нових трейдів, емісія подій
- **Debug повідомлення:** Деталі опитування кожного символу
- **Помилки:** Проблеми з API, мережеві помилки

### Метрики
- Кількість оброблених трейдів
- Частота виявлення нових трейдів
- Середній час між опитуваннями

## Обробка помилок

### Стратегії відновлення
1. **API помилки:** Продовження опитування інших символів
2. **Мережеві проблеми:** Повторні спроби при наступному циклі
3. **Парсинг помилки:** Логування та пропуск проблемних трейдів

### Graceful degradation
При неможливості опитування окремих символів продовжує моніторинг інших.

## Тестування

### Інтеграційні тести
- Валідація коректності трансформації трейдів в події
- Перевірка фільтрації дублікатів
- Тестування роботи в різних режимах

### Модульні тести
- Перевірка парсингу трейдів Binance
- Валідація формату payload
- Тестування логіки дедуплікації

## Безпека

### Read-only доступ
- Використання тільки read-only API ключів
- Неможливість виконання торгових операцій
- Мінімальні дозволи для моніторингу

### Аудит
Всі виявлені трейди логуються для аудиту та debugging.
