# Домен Account Balance (Баланс Рахунку)

## Загальна інформація

**Ідентифікатор домену:** `account_balance`  
**Версія:** FSMP-P1-T04  
**Роль в системі:** Джерело даних про стан рахунку та позицій

## Архітектурна роль

Домен `account_balance` є фундаментальним компонентом системи Aurora, що забезпечує моніторинг фінансового стану торгового рахунку. Він виступає як міст між біржовими API та внутрішньою логікою системи, перетворюючи сирі дані балансу в структуровані FSM події.

### Відповідальність
- Отримання даних про баланс активів з Binance Futures API
- Моніторинг відкритих позицій
- Перетворення сирих API даних в стандартизовані події FSM
- Забезпечення актуальності фінансового стану для прийняття рішень

## Структура домену

### Основні компоненти

#### AccountConnector
Головний клас домену, що реалізує підключення до Binance API.

**Ініціалізація:**
- Налаштування BinanceAdapter на основі `trading_mode`
- Вибір API ключів (live/testnet) залежно від режиму роботи
- Налаштування інтервалу опитування (за замовчуванням 30 секунд)

**Методи життєвого циклу:**
- `start()` - запуск фонового моніторингу
- `stop()` - зупинка моніторингу та закриття з'єднань

### Внутрішня архітектура

#### Моніторинговий цикл
```
_monitor_loop() -> _fetch_and_emit_account_data()
    ├── Отримання балансу (/fapi/v2/balance)
    ├── Отримання позицій (/fapi/v2/positionRisk)
    ├── Емісія подій FSM
    └── Очікування інтервалу опитування
```

#### Обробка даних
1. **Баланс активів:** Фільтрація активів з ненульовим балансом
2. **Позиції:** Фільтрація відкритих позицій (positionAmt != 0)
3. **Перетворення:** Конвертація в Decimal для точності обчислень

## FSM події

### Генеровані події

#### EVT:BALANCE_UPDATE_RECEIVED
**Частота:** Кожні 30 секунд (або за конфігурацією)  
**Направлення:** Decision Making, Risk Management, Position Tracking  

**Payload структура:**
```json
{
  "assets": [
    {
      "asset": "USDT",
      "balance": "1000.50",
      "crossUnPnl": "25.30",
      "crossWalletBalance": "975.20",
      "updateTime": 1640995200000
    }
  ],
  "updateTime": 1640995200000
}
```

**Опис:** Передає актуальний баланс всіх активів з ненульовими залишками.

#### EVT:ACCOUNT_UPDATE_RECEIVED
**Частота:** Кожні 30 секунд (або за конфігурацією)  
**Направлення:** Position Tracking, Risk Management, Decision Making  

**Payload структура:**
```json
{
  "totalWalletBalance": "1000.50",
  "totalUnrealizedProfit": "25.30",
  "totalCrossWalletBalance": "975.20",
  "positions": [
    {
      "symbol": "BTCUSDT",
      "positionAmt": "0.001",
      "entryPrice": "50000.00",
      "unRealizedProfit": "5.25",
      "leverage": 10,
      "marginType": "cross",
      "markPrice": "50250.00",
      "liquidationPrice": "45000.00"
    }
  ],
  "updateTime": 1640995200000
}
```

**Опис:** Передає інформацію про всі відкриті позиції та загальний стан рахунку.

### Споживані події
Домен не споживає зовнішні події - працює автономно.

## Взаємодія з іншими доменами

### Синхронні зв'язки

#### Position Tracking
- **Вхід:** EVT:ACCOUNT_UPDATE_RECEIVED
- **Використання:** Оновлення внутрішнього стану позицій
- **Частота:** Реального часу (30 сек)

#### Risk Management
- **Вхід:** EVT:BALANCE_UPDATE_RECEIVED, EVT:ACCOUNT_UPDATE_RECEIVED
- **Використання:** Розрахунок ризиків портфеля, перевірка лімітів
- **Частота:** Реального часу (30 сек)

#### Decision Making
- **Вхід:** EVT:BALANCE_UPDATE_RECEIVED
- **Використання:** Оцінка доступного капіталу для нових позицій
- **Частота:** Реального часу (30 сек)

### Асинхронні залежності
Домен працює незалежно від інших компонентів, але його дані критичні для прийняття рішень.

## Конфігурація

### Основні параметри
```yaml
trading_mode: "hybrid_live_data_testnet_exec"  # Впливає на вибір API ключів

binance_api:
  live:
    api_key: "${BINANCE_LIVE_API_KEY}"
    api_secret: "${BINANCE_LIVE_API_SECRET}"
    rest_url: "https://fapi.binance.com"
  testnet:
    api_key: "${BINANCE_TESTNET_API_KEY}"
    api_secret: "${BINANCE_TESTNET_API_SECRET}"
    rest_url: "https://testnet.binancefuture.com"

account_observer:
  poll_interval: 30  # Інтервал опитування в секундах
```

### Режими роботи
- **live:** Використання бойових API ключів Binance
- **testnet:** Використання тестових API ключів
- **hybrid_live_data_testnet_exec:** Автоматичний вибір залежно від домену

## Моніторинг та діагностика

### Логування
- **Інформаційні повідомлення:** Успішне отримання даних, кількість активів/позицій
- **Попередження:** Відсутність USDT в балансі, проблеми з API
- **Помилки:** Невдачі з'єднання з API, проблеми парсингу даних

### Метрики
- Частота успішних оновлень балансу
- Частота успішних оновлень позицій
- Розмір затримки між API викликами та емісією подій

## Обробка помилок

### Стратегії відновлення
1. **API помилки:** Повторні спроби з експоненціальним backoff
2. **Невалідні дані:** Логування та пропуск некоректних записів
3. **Мережеві проблеми:** Продовження роботи з останніми відомими даними

### Graceful degradation
При неможливості отримання даних з API домен продовжує роботу з останніми відомими значеннями, логуючи проблеми.
