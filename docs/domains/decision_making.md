# Домен Decision Making (Прийняття Рішень)

## Загальна інформація

**Ідентифікатор домену:** `decision_making`  
**Роль в системі:** Центр логіки прийняття торгових рішень

## Архітектурна роль

Домен `decision_making` є мозком торгової системи Aurora. Він агрегує дані з усіх аналітичних доменів (ризики, особливості, портфель, режим ринку) та приймає рішення про торгівлю на основі комплексної оцінки.

### Відповідальність
- Агрегація сигналів з різних джерел (OBI, TFI, ризики, режим)
- Розрахунок композитного торгового сигналу
- Визначення розміру позиції на основі equity та ризиків
- Генерація торгових інтентів для виконання

## Структура домену

### Основні компоненти

#### DecisionMaking
Головний клас домену, що реалізує логіку прийняття рішень.

**Ініціалізація:**
- Підписка на події від всіх аналітичних доменів
- Завантаження конфігурації ваг сигналів та порогів
- Ініціалізація стану символів та глобального контексту

**Методи життєвого циклу:**
- `start()` - запуск компоненту
- `stop()` - зупинка компоненту

### Внутрішня архітектура

#### Агрегація даних
```
on_features() + on_risk() + on_portfolio() + on_regime()
    ├── Збереження даних в symbol_states
    ├── Перевірка готовності всіх компонент
    └── Тригер прийняття рішення
```

#### Логіка прийняття рішень
```
_make_decision_for_symbol()
    ├── Перевірка дозволу на торгівлю від Risk Management
    ├── Розрахунок композитного сигналу
    ├── Фільтрація за ринковим режимом
    ├── Розрахунок розміру позиції
    └── Генерація EVT:TRADE_INTENT_PROPOSED
```

**Джерело:** Position Tracking

**Джерело:** Regime Detector  
**Використання:** Фільтрація сигналів за ринковим режимом

## Взаємодія з іншими доменами

### Синхронні зв'язки

#### Feature Engineering
- **Вхід:** EVT:FEATURES_CALCULATED
- **Використання:** OBI, TFI, delta_price для композитного сигналу
- **Частота:** Реального часу

#### Risk Management
- **Вхід:** EVT:RISK_ASSESSMENT_COMPLETED
- **Використання:** Перевірка is_trading_allowed
- **Частота:** Реального часу

#### Position Tracking
- **Вхід:** EVT:PORTFOLIO_STATE_UPDATED
- **Використання:** Доступний equity для sizing
- **Частота:** Реального часу

#### Regime Detector
- **Вхід:** EVT:REGIME_DETECTED
- **Використання:** Фільтрація тренд-противих сигналів
- **Частота:** Реального часу

#### Execution Management
- **Вихід:** EVT:TRADE_INTENT_PROPOSED
- **Використання:** Виконання торгового інтенту
- **Частота:** Подієво

### Асинхронні залежності
Залежить від всіх аналітичних доменів для прийняття обґрунтованих рішень.

## Алгоритм прийняття рішень

### Композитний сигнал
```
signal_score = OBI × w_obi + TFI × w_tfi + delta_price × w_delta_price
```

**Пороги:**
- `signal_score > threshold` → BUY
- `signal_score < -threshold` → SELL
- `|signal_score| ≤ threshold` → HOLD

### Розмір позиції
```
position_size_usd = min(liquidity_cap, equity × risk_fraction)
quantity = position_size_usd / price
rounded_quantity = floor(quantity / step_size) × step_size
```

### Фільтри
1. **Risk Filter:** Перевірка `is_trading_allowed`
2. **Regime Filter:** Відхилення контр-трендових сигналів
3. **Equity Filter:** Відхилення при недостатньому equity
4. **Size Filter:** Мінімальний розмір позиції

## Конфігурація

### Основні параметри

```yaml
decision:
  signal_weights:

```
