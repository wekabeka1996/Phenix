# Домен Market Data (Ринкові Дані)

## Загальна інформація

**Ідентифікатор домену:** `market_data`  
**Версія:** FSMP-P1-T03  
**Роль в системі:** Джерело ринкових даних для аналізу та прийняття рішень

## Архітектурна роль

Домен `market_data` є фундаментом аналітичної частини системи Aurora. Він забезпечує постійний потік ринкових даних через REST API Binance, перетворюючи сирі Kline дані в стандартизовані події для подальшого аналізу.

### Відповідальність
- Отримання 1-хвилинних Kline даних з Binance Futures
- Перетворення технічних індикаторів в стандартизований формат
- Тегування джерела даних (live/testnet) для коректного аналізу
- Забезпечення системи актуальними ринковими даними

## Структура домену

### Основні компоненти

#### MarketDataConnector
Головний клас домену, що реалізує отримання та обробку ринкових даних.

**Ініціалізація:**
- Налаштування BinanceAdapter на основі доменного режиму
- Вибір API ключів залежно від конфігурації domain_configuration
- Налаштування списку символів та інтервалу опитування

**Методи життєвого циклу:**
- `start()` - запуск фонового опитування
- `stop()` - зупинка та закриття з'єднань

### Внутрішня архітектура

#### Цикл отримання даних
```
_poll_loop() -> _fetch_and_emit_data()
    ├── Опитування кожного символу з конфігурації
    ├── Отримання останніх 1m Kline даних
    ├── Перетворення в MARKET_TICK_RECEIVED події
    └── Очікування інтервалу опитування
```

#### Обробка Kline даних
1. **Парсинг:** Розбір масиву Kline у значущі компоненти
2. **Нормалізація:** Перетворення в Decimal для точності
3. **Проксі значення:** Створення bid/ask з close price для сумісності

## FSM події

### Генеровані події

#### EVT:MARKET_TICK_RECEIVED
**Частота:** Кожні 5 секунд на символ (за замовчуванням)  
**Направлення:** Feature Engineering, Decision Making, Risk Management  

**Payload структура:**
```json
{
  "ts": 1640995200000,
  "symbol": "BTCUSDT",
  "price": "50000.00",
  "bid": "50000.00",
  "ask": "50000.00",
  "mid": "50000.00",
  "bid_size": "1",
  "ask_size": "1",
  "buy_volume": "100.5",
  "sell_volume": "95.3",
  "data_type": "kline_1m",
  "data_source": "live"
}
```

**Опис:** Передає нормалізовані ринкові дані для аналізу та прийняття рішень.

### Споживані події
Домен не споживає зовнішні події - працює автономно.

## Взаємодія з іншими доменами

### Синхронні зв'язки

#### Feature Engineering
- **Вхід:** EVT:MARKET_TICK_RECEIVED
- **Використання:** Розрахунок технічних індикаторів (OBI, TFI, delta_price)
- **Частота:** Реального часу (5 сек на символ)

#### Decision Making
- **Вхід:** EVT:MARKET_TICK_RECEIVED
- **Використання:** Оцінка ринкових умов для прийняття рішень
- **Частота:** Реального часу (5 сек на символ)

#### Risk Management
- **Вхід:** EVT:MARKET_TICK_RECEIVED
- **Використання:** Моніторинг волатильності та ринкових ризиків
- **Частота:** Реального часу (5 сек на символ)

### Асинхронні залежності
Домен є критичним джерелом даних для всієї аналітичної ланцюжка.

## Конфігурація

### Основні параметри
```yaml
trading_mode: "hybrid_live_data_testnet_exec"

domain_configuration:
  market_data:
    trading_mode: "live"  # Завжди live для отримання реальних даних

binance_api:
  live:
    api_key: "${BINANCE_LIVE_API_KEY}"
    api_secret: "${BINANCE_LIVE_API_SECRET}"
    rest_url: "https://fapi.binance.com"

system:
  trading:
    symbols_to_track:
      - BTCUSDT
      - ETHUSDT
    market_data:
      poll_interval_sec: 5
```

### Режими роботи
- **live:** Отримання бойових ринкових даних
- **testnet:** Отримання тестових ринкових даних
- **hybrid:** Зазвичай live для аналізу, testnet для виконання

## Моніторинг та діагностика

### Логування
- **Інформаційні повідомлення:** Запуск/зупинка конектора, зміна джерела даних
- **Попередження:** Відсутність даних для символу
- **Помилки:** Проблеми з API, парсинг помилки

### Метрики
- Частота успішного отримання даних
- Затримка між опитуваннями та емісією подій
- Кількість символів з дійсними даними

## Обробка помилок

### Стратегії відновлення
1. **API помилки:** Продовження опитування інших символів
2. **Невалідні дані:** Логування та пропуск проблемних Kline
3. **Мережеві проблеми:** Повторні спроби при наступному циклі

### Graceful degradation
При проблемах з окремими символами продовжує збір даних для інших.

## Тестування

- Перевірка роботи в різних режимах (live/testnet)

### Модульні тести

- Використання API ключів з мінімальними дозволами
- Тільки читання публічних ринкових даних
