## 1. Executive Verdict

Phase 6 is a review gate.

It exists to evaluate whether the existing shadow judge line and the Phase 5 offline evidence line are strong enough to justify any bounded promotion candidate for later package work.

Phase 6 is not a runtime promotion package.

It does not widen `JudgeCortexConfig` admission, does not implement `hybrid_advisory`, does not implement guarded authority, does not move ownership away from `decision_making` or `execution_position`, and does not create any direct LLM-to-exchange path.

No Phase 6 outcome in this artifact directly authorizes runtime behavior.

## 2. Problem Framing

Phase 5 delivered an offline simulator and related evidence outputs. That closes the evidence-production gap, not the promotion decision.

Phase 6 exists because replayable shadow evidence can now be reviewed, compared, segmented, and challenged without silently widening runtime authority.

The risk Phase 6 must localize is authority drift. The specific failure mode is treating simulator existence, a passing replay harness, or a handful of favorable examples as proof that advisory or guarded authority is safe.

Phase 6 therefore separates two questions that must not be collapsed:

- Has the repo produced enough bounded evidence to review the judge line seriously?
- Has that evidence cleared a promotion threshold for any later package?

The first question may be yes while the second remains no.

## 3. FACTS

The following are current repo-supported truths.

1. The LLM Judge concept defines a bounded policy-evaluation line with separate entry and lifecycle verdict families, a chamber-based structure, and no execution-truth ownership.
2. The concept laws explicitly require additive-only rollout, contract-first behavior, replayability, shadow-first validation, and no direct LLM-to-exchange path.
3. The repository rollout meaning is normalized so that Phase 5 is Shadow Economic Simulator and Phase 6 is Validation and Promotion Review.
4. The current shipped judge runtime admits only `off` and `shadow`. `hybrid_advisory`, `guarded_entry_authority`, and `guarded_lifecycle_authority` remain rejected by config admission.
5. alpha_search is a dual-shape strategy-analysis domain. It owns alpha scoring, judge shadow evidence emission, the offline simulator subtree, and the optional shutdown-time export seam.
6. alpha_search does not own decision policy, execution authority, mode widening beyond `off` and `shadow`, or Phase 6 admission semantics.
7. The embedded alpha_search path emits shadow `JUDGE_*` artifacts for expert output, chamber aggregation, evidence assembly, entry verdicts, and optionally lifecycle verdicts, but the documented boundary remains shadow-only evidence production.
8. The Phase 5 simulator subtree is materially implemented and validated as an offline evidence line.
9. The accepted shutdown export seam is bounded automation of the same offline simulator path after session end. It is not live decision authority, not a simulator runtime mode, and not a policy bridge into `decision_making`.
10. The simulator remains configured through `config/judge_simulator.yaml`, not through Aurora DomainsConfig and not through a widened live judge mode.
11. The current summary output exposes `policy_readiness_notes` as informational heuristics. It does not encode a promotion verdict and does not itself authorize Phase 6 decisions.
12. Phase 5 package reports and closure authority explicitly defer promotion review, advisory integration, and mode widening beyond the current shadow boundary.
13. `decision_making` remains the policy owner for live trade admission semantics.
14. `execution_position` remains the execution truth owner for live order and position lifecycle semantics.
15. No current repository authority states that promotion beyond shadow has been proven.

## 4. INFERENCES

The following can be concluded from the current evidence base, but they remain conclusions rather than direct runtime facts.

1. Phase 5 gives Phase 6 a real review substrate: replayable artifacts, deterministic simulator outputs, disagreement analysis, calibration outputs, and bounded summary reporting.
2. Phase 6 can now review value contribution separately at the expert, chamber, verdict, and economic layers instead of arguing from architecture alone.
3. Because current admission is still `off` or `shadow`, any future non-shadow surface must be treated as a separate contract and implementation decision, not as an automatic continuation of Phase 5.
4. Entry-side review is better grounded than lifecycle-side review because the current delivered line is strongest on entry verdict production and simulator economics.
5. A safe Phase 6 outcome may still be to remain shadow-only even if the simulator line is technically sound.
6. Recommendation-only or `hybrid_advisory` planning can be considered only as bounded future candidates, not as current runtime truth.

## 5. ASSUMPTIONS

The following assumptions may be used during review, but none are yet proven by the current repo alone.

1. The available shadow artifacts are representative enough across symbols, regimes, and sessions to support a meaningful promotion review.
2. Outcome data supplied to the simulator is accurate enough to support economic conclusions.
3. The revived legacy experts, where used, remain stable enough under replay for comparison across runs.
4. The current confidence outputs are coherent enough to support later calibration judgments.
5. If a bounded advisory surface is ever proposed, operators will be able to inspect and understand it without hidden authority transfer.

## 6. UNKNOWNS

The following remain unproven and must stay unproven until Phase 6 evidence explicitly addresses them.

1. Economic benefit versus incumbent strategy outputs is not yet proven.
2. False positive, false suppression, and `UNKNOWN` behavior profiles are not yet proven acceptable across regimes.
3. Lifecycle verdict usefulness is not yet proven.
4. Robustness of revived legacy experts, if present in the effective judge line, is not yet proven under wider replay coverage.
5. Confidence quality and calibration stability are not yet proven under drift, regime changes, or symbol segmentation.
6. Disagreement patterns are not yet proven to be decision-useful rather than merely descriptive.
7. Any advisory surface is not yet proven safe enough for bounded exposure.

## 7. Promotion Review Questions

Phase 6 must answer the following review questions explicitly.

1. Does the entry chamber add measurable signal value beyond incumbent strategy outputs?
2. Does the final judge add measurable value beyond chamber-only aggregation?
3. Are entry verdicts stable under replay, segmentation, and repeated simulation runs?
4. Are `SUPPRESS` and `UNKNOWN` behaviors bounded, explainable, and operationally acceptable?
5. Does the lifecycle chamber produce evidence that is decision-useful, or is it still mostly a conceptual surface?
6. Does the verdict mapping layer preserve consistent semantics between chamber outputs and final verdict outputs?
7. Does the simulator-derived economic view show net value after fee, slippage, and disagreement analysis?
8. Are confidence scores and calibration artifacts good enough to support any bounded review outcome?
9. Does the judge line add value beyond chamber output alone, or is the extra final-judge layer not yet justified?
10. Is any bounded recommendation-only or advisory candidate safe enough to justify a later contract package?
11. If evidence is weak or contradictory, is the correct decision to remain shadow-only or reject promotion entirely?

## 8. Review Surfaces

Phase 6 review must keep the following surfaces separate.

| Surface | Current truth | Review focus | Non-goal |
|---|---|---|---|
| Entry chamber | Exists as part of the shadow chain and is the strongest evidence-bearing chamber surface today | admissibility quality, consensus usefulness, suppression behavior, value over incumbent outputs | treating chamber presence as promotion proof |
| Lifecycle chamber | Exists as a defined surface but is weaker in current evidence posture | whether lifecycle outputs are meaningful, stable, and worth further investment | assuming lifecycle authority is ready |
| Final judge | Exists as verdict synthesis over chamber and evidence inputs | incremental value over chamber-only aggregation, reasoning stability, fail-closed behavior | assuming final-judge presence implies advisory readiness |
| Verdict mapping layer | Maps chamber and evidence state into typed verdict outputs | semantic consistency, dissent preservation, applied-versus-not-applied clarity | widening live mode admission |
| Simulator-derived economic review | Offline replay and economics line is materially implemented | fee/slippage-adjusted value, outcome correlation, segment-level performance | using simulator existence as standalone promotion evidence |
| Disagreement analysis | Implemented in Phase 5 evidence outputs | whether disagreement reveals useful boundaries, failure modes, or gating conditions | confusing descriptive disagreement with actionable improvement |
| Calibration and confidence quality | Calibration outputs exist | confidence coherence, ranking quality, threshold sensitivity, segmentation robustness | converting heuristics into silent gates |

## 9. Validation Matrix

Phase 6 requires explicit evidence classes. No single class is sufficient on its own.

| Evidence class | What it must prove | Minimum evidence shape | Fails if |
|---|---|---|---|
| Structural validation | contracts, docs, config boundaries, and ownership claims remain aligned | config admission still bounded to `off` or `shadow`; event and simulator boundaries remain additive; review artifacts map to current repo truth | the review depends on hidden mode widening, undocumented bridges, or authority drift |
| Behavioral validation | shadow chain behaves as described and fails closed where intended | representative tests, artifact traces, and documented failure semantics for expert, chamber, evidence, and verdict paths | review assumes behavior not exercised by current runtime or tests |
| Replay validation | verdict and simulator outputs are reproducible enough to review | repeated replay runs, stable joins, deterministic or explained outputs, bounded variance where nondeterminism exists | conclusions depend on unreproducible outcomes |
| Economic validation | the judge line shows or fails to show economic usefulness under realistic costs | simulator summaries, fee/slippage-adjusted comparisons, segment-level outcome analysis, suppression and unknown cost accounting | only gross examples or anecdotal wins are used |
| Comparative validation | the judge line is compared against the right baselines | incumbent strategy outputs, chamber-only baseline, final-judge baseline, and no-judge baseline where relevant | value is asserted without a baseline |
| Operator and observability validation | any later candidate would remain inspectable and bounded | traceable artifacts, readable diagnostics, explicit reason surfaces, clear non-application semantics | a later candidate would rely on hidden decisions or opaque verdict injection |

Required Phase 6 rule:

- A positive result in one evidence class cannot compensate for a missing or failed result in structural or operator and observability validation.

## 10. Promotion Ladder

The promotion ladder defines bounded review outcomes only. It does not authorize implementation.

1. **Reject promotion**
   Evidence shows negative value, unacceptable instability, or unacceptable operational opacity.
2. **Require more evidence**
   Evidence is incomplete, contradictory, undersampled, or structurally misaligned.
3. **Remain shadow-only**
   Evidence is coherent enough to keep the line alive, but not strong enough to justify a new surface.
4. **Admit recommendation-only review candidate**
   Evidence may justify a later package that exposes bounded non-authoritative recommendations outside live trade admission. This remains planning-only.
5. **Admit `hybrid_advisory` planning only**
   Evidence may justify a separate promotion-boundary contract package to evaluate a future `hybrid_advisory` surface. This is still not implementation authority.

Phase 6 does not directly admit `guarded_entry_authority` or `guarded_lifecycle_authority` in runtime.

Any movement above shadow-only requires a later explicit package with typed contracts, ownership review, observability requirements, and fail-closed admission logic.

## 11. Forbidden Shortcuts

The following shortcuts are explicitly forbidden.

1. Direct LLM execution control.
2. Hidden verdict injection into live trade admission.
3. Silent revival of legacy math into Aurora policy or execution flows.
4. Untyped mode widening.
5. Promotion based only on anecdotal examples.
6. Promotion based only on simulator existence.
7. Promotion based only on `policy_readiness_notes` heuristics.
8. Reinterpreting alpha_search evidence ownership as decision or execution authority.

## 12. Required Future Packages

If Phase 6 produces a bounded positive candidate, the next work must still be packaged in order.

1. **Validation artifact tooling package**
   Additional reporting, segmentation, review automation, or evidence-shaping work needed to make review decisions legible and reproducible.
2. **Promotion-boundary contract package**
   Typed contracts, explicit scope, observability, and fail-closed rules for any later recommendation-only or `hybrid_advisory` surface.
3. **Guarded implementation package, only if admitted later**
   Runtime code changes may be considered only after the first two package classes exist and the bounded promotion candidate is explicitly approved.

No later package may bypass the contract package and go directly from Phase 6 review language to runtime authority.

## 13. Exit Gate for Phase 6

Phase 6 is complete only when all of the following are true.

1. The current authority boundary is documented without contradiction: alpha_search remains evidence owner, `decision_making` remains policy owner, and `execution_position` remains execution truth owner.
2. Structural, behavioral, replay, economic, comparative, and operator and observability evidence have each been reviewed explicitly.
3. The review answers are recorded separately for entry chamber, lifecycle chamber, final judge, verdict mapping, simulator economics, disagreement analysis, and calibration quality.
4. Unproven areas remain explicitly labeled as assumptions or unknowns rather than being smuggled into conclusions.
5. A promotion-ladder outcome is chosen and justified.
6. If the outcome is above shadow-only, a separate follow-on package category is named, but no implementation is folded into Phase 6 itself.
7. If the outcome is remain shadow-only, require more evidence, or reject promotion, that boundary is stated explicitly with no hidden reopening of runtime authority.
