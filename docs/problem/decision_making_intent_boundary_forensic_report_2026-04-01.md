## 4. Root-Cause Analysis

- Kelly fraction drift. FACT: builder сериализует `size.kelly_fraction` через fallback read в `apps/reference/domains/decision_making/intent_builder.py:258-261`. FACT: SSOT `KellyConfig` в `apps/reference/config_models.py:324-330` не содержит `fraction`. FACT: runtime loaded config тоже не содержал `fraction`. Root cause: boundary читает несуществующий config path и тихо подставляет hardcoded default. Effect: schema-required field существует в payload, но не имеет SSOT provenance. Masking: test harness искусственно добавляет `fraction` в `tests/unit/llm/test_llm_intent_builder_contract.py:42`.
- Hardcoded `p` и payoff drift. FACT: builder пишет `p = 0.75` и `payoff_ratio_r = 2.0` через `apps/reference/domains/decision_making/intent_builder.py:273`. FACT: schema требует именно эти поля как boundary contract в `apps/reference/domains/decision_making/schemas/trade_intent_v1.json:23-30` и `apps/reference/domains/decision_making/schemas/trade_intent_v1.json:384-385`. FACT: live YAML `payoff_ratio_r` равен `1.5` в `config/aurora/strategies/aurora.yaml:246`. Root cause: payload builder не берет эти значения ни из live config, ни из upstream scoring contract, а сериализует literals. Effect: WAL и live proposed intent несут semantically wrong metadata. Masking: schema/test coverage проверяет presence, а не provenance; test-only Kelly math в `tests/unit/decision_making/test_fail_closed_config.py:44-93` может создавать ложное впечатление, что runtime эти значения вычисляет.
- Lifecycle truth gaps. FACT: invalid qty, missing TCA, missing risk budget, builder arbitration blocked и warmup blocker paths не маршрутизируются через canonical truth helper в `apps/reference/domains/decision_making/intent_builder.py:201`, `apps/reference/domains/decision_making/intent_builder.py:220`, `apps/reference/domains/decision_making/intent_builder.py:230`, `apps/reference/domains/decision_making/intent_builder.py:301`, `apps/reference/domains/decision_making/intent_builder.py:141`. FACT: warmup helper в `apps/reference/domains/decision_making/readiness_gates.py:149-301` на всех not-ready exits делает blocked-only handling, тогда как canonical defer в этом модуле появляется только для degraded context в `apps/reference/domains/decision_making/readiness_gates.py:453`. Root cause: terminal outcomes размазаны по нескольким helper-ам без единой exhaustiveness map. Effect: stop path может быть operationally blocked, но forensic truth stream не получит canonical reason event. Masking: blocked counters все равно растут через `apps/reference/domains/decision_making/intent_emitter.py:249-260`, а отдельные defer paths действительно работают, что скрывает дыры.
- Reject swallow. FACT: reject helper помечен как best-effort в `apps/reference/domains/decision_making/intent_emitter.py:168`. FACT: любой exception глотается в `apps/reference/domains/decision_making/intent_emitter.py:215`. FACT: reject WAL writer сам по себе только пишет WAL и делает log on `None` result в `apps/reference/domains/decision_making/trade_intent_reject_wal.py:5-133`. Root cause: reject emission спроектирован как non-authoritative side effect вместо contractually significant boundary action. Effect: при writer exception исчезают и WAL truth, и live reject event; при live emit exception сохраняется только partial truth; caller считает, что reject path завершился нормально. Masking: `wal.append` returning `None` логируется внутри helper, но thrown exceptions выше по стеку не дают caller-visible signal.

## 8. Repair Options

- Вариант A, минимальный безопасный пакет. Локально убрать swallow в reject path: либо propagate failure caller-у, либо как минимум возвращать success/failure status и логировать/метризировать каждый exception. Далее свести все builder early exits к единой terminal helper map, которая заставляет выбрать один из canonical outcomes: `TRADE_INTENT_REJECTED`, `INTENT_DEFERRED`, `DECISION_BLOCKED` или `STRATEGY_DECISION_BLOCKED`. Это наименее рискованный путь и он лучше всего соответствует требованию minimal localized fixes.
- Вариант B, contract alignment для payload. Если `p`, `payoff_ratio_r` и `size.kelly_fraction` действительно должны быть authoritative на этой boundary, их надо получать только из реального upstream contract или live SSOT config, а не синтезировать. Если boundary не является authoritative source для этих полей, ломать текущую schema нельзя; нужна новая версия contract, потому что repository law запрещает тихие breaking changes.
- Вариант C, stronger refactor. Ввести маленький internal outcome model для всех terminal branch states в builder/readiness/gateway, после чего иметь один centralized emitter/router. Это глубже, но почти полностью убирает class of bugs, где отдельная ветка забыла emitнуть truth.
- Для тестов минимальный пакет должен убрать mock-only fraction injection, выровнять expectations на normalized NRR codes и обновить stale SG stubs до актуального runtime contract.

## 9. Recommended Package Order

1. Reject-path reliability first. Пока reject failures глотаются, любой следующий ремонт остается частично невидимым в production forensics.
2. Lifecycle truth closure second. После того как failures станут видимыми, нужно закрыть все builder/readiness early returns единым canonical outcome contract. Иначе monitoring и WAL truth продолжат содержать дыры.
3. Payload contract alignment third. Только после стабилизации lifecycle truth стоит править `p`, `payoff_ratio_r` и `size.kelly_fraction`, иначе будет трудно отличить semantic drift от transport loss.
4. Test suite repair fourth. Тесты нужно обновить после стабилизации live semantics, чтобы они фиксировали именно runtime truth, а не старые mock conventions.
5. Optional stronger refactor last. Centralized terminal outcome routing имеет смысл только после локального ремонта, когда станет понятно, какая именно canonical semantics нужна для каждой branch category.
