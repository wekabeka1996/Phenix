## 🔹 Концепція шадоу-середовища

Це не просто тестовий запуск — це **“середовище повного циклу з ізольованим контуром подій”**, яке:

1. не взаємодіє з реальною біржею;
2. емулятор потоків (market data, fills, network latency);
3. фіксує кожен крок FSM у часовій послідовності;
4. виводить “кардіограму” (ланцюг дій і рішень) як граф чи DAG.

---

## ⚙️ Структура Shadow-середовища

```
shadow_env/
├── adapters/
│   └── mock_exchange_adapter.py        # емуляція біржі, ACK, fills, delays
├── core/
│   ├── shadow_bus.py                   # подієвий шина / FSM event router
│   ├── shadow_logger.py                # окреме JSONL-логування (із timestamp, event, domain)
│   └── shadow_metrics.py               # збір метрик FSM переходів
├── orchestrator.py                     # головний сценарій "full run"
├── visualizer.py                       # генератор схеми ланцюга дій
└── configs/shadow.yaml                 # ізольована конфігурація
```

---

## 🔹 Алгоритм сценарію `orchestrator.py`

1. Ініціалізує компоненти: adapter, bus, logger.
2. Створює один TradeIntent (`BUY` або `SELL`).
3. Послідовно викликає:

   ```
   ENTRY_PLACED → BRACKETS_PLACED → MONITORING → TP_HIT (або SL_HIT) → CLOSED
   ```
4. Всі події проходять через `shadow_bus.publish(event)`, який:

   * записує у JSONL (через shadow_logger);
   * зберігає зв’язки у структуру DAG (`(prev_state → next_state)`).

## 🔹 Візуалізація — `visualizer.py`

Використай Graphviz або Mermaid-генератор:

```python
import json
from graphviz import Digraph

def visualize(log_file="shadow_logs.jsonl", out_file="fsm_chain.svg"):
    g = Digraph("ShadowFSM", format="svg")
    with open(log_file) as f:
        events = [json.loads(line) for line in f]
    last = None
    for e in events:
        evt = e["event"]
        g.node(evt, evt, shape="box")
        if last:
            g.edge(last, evt)
        last = evt
    g.render(out_file, view=False)
```

→ отримаєш граф виду:

```
ENTRY_PLACED → BRACKETS_PLACED → MONITORING → TP_HIT → CLOSED
```

Це фактично **автоматична схема ланцюга дій і рішень** системи.

## 🔹 Що продумати перед реалізацією

| Компонент              | Запитання перед кодом                                                       |
| ---------------------- | --------------------------------------------------------------------------- |
| **Shadow adapter**     | які затримки та помилки симулюємо (ACK delay, network jitter, reject)?      |
| **Shadow bus**         | чи всі FSM-події проходять через одну publish/subscriber систему?           |
| **Shadow logger**      | чи логувати тільки state-transition чи ще й параметри дій (price, latency)? |
| **Visualizer**         | як групувати події: по rid чи по symbol?                                    |
| **Config shadow.yaml** | чи запускати один символ чи весь universe?                                  |
| **Replay**             | чи хочеш зберігати seed (щоб відтворити точну симуляцію)?                   |

## 🔹 Як це працює в циклі

```
TradeIntent → open_with_bracket()
│
├─ Adapter.place_order(entry)
├─ Adapter.place_order(TP, SL)
│
└─ ShadowBus.publish(event)
     ↓
  ShadowLogger.write(JSONL)
     ↓
  ShadowMetrics.count(state_transition)
     ↓
  Visualizer.build_graph()
```

У результаті після одного циклу:

* ти отримуєш `shadow_logs.jsonl`
* і одразу `fsm_chain.svg` з реальним ланцюгом подій
  (жодного “ручного малювання”).
