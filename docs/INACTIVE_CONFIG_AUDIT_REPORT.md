# Звіт щодо вимкнених та неактивних конфігурацій (Inactive Configuration Audit Report)

## 1. Вступ
Мета цього документа — детальний аналіз полів конфігурації у теці `config/aurora`, які наразі вимкнені (мають значення `false`, `disable` або еквівалентні). Дослідження описує логіку кожного поля, причини вимкнення, та надає докази з комітів і внутрішньої документації проєкту. Аналіз базується на збережених логах, файлах звітності (artifacts/reports) та системних паспортах.

## 2. Аналіз полів конфігурації

### 2.1. `microstructure_veto.enabled` та `obi_confirm_enabled`
- **Файл:** `config/aurora/strategies/mean_reversion.yaml`
- **Значення:** `false`
- **Логіка:** Це дворівневий (bivariate) фільтр на рівні обробника стратегії (handler-level overlay). Він використовує Trade Flow Imbalance (TFI) та реакцію ціни (price reaction/wick absorption), щоб блокувати токсичні сигнали продовження руху та дозволяти входи на поглинанні. `obi_confirm_enabled` додатково використовує Order Book Imbalance як підтверджувальний фактор.
- **Причина вимкнення:** Логіка суворо відхиляє операції при відсутності даних (strict fail-closed). Оптимальне калібрування порогів потребує тестування на реальних ринкових даних (live market testing). Крім того, виявлено проблеми з пайплайном даних (відсутність вкладеного `features.price_motion` у очікуваному форматі). Тому функція вимкнена за замовчуванням до завершення валідації.
- **Докази:** Документи `REPORT_IMPLEMENTED_MR_VECTORS_V1_V2.md`, `INDEPENDENT_AUDIT_REPORT_MR_VECTORS_V1_V2.md`, `mean_reversion_state_machine_passport.md`.

### 2.2. `strategies.llm_microstructure.safety_gates.enabled`
- **Файл:** `config/aurora/strategies/llm_microstructure.yaml`
- **Значення:** `false`
- **Логіка:** Вмикає внутрішні захисні механізми (safety gates), такі як перевірка впевненості режиму (regime confidence) та стресу системи.
- **Причина вимкнення (AUDIT-FIX-2026-03-19):** Гейт `regime_confidence` помилково блокував роботу через відсутність даних для символів, які використовуються виключно зовнішньою LLM-системою (вони не проходять через звичайний пайплайн `aurora FE`). Енфорсмент контрактів для них відбувається на рівні HTTP Ingress, а LLM є єдиним органом прийняття рішень.
- **Докази:** Коментарі розробників у файлі `llm_microstructure.yaml`.

### 2.3. `trading.execution.fsm_periodic_cleanup_enabled`
- **Файл:** `config/aurora/trading.yaml`
- **Значення:** `false`
- **Логіка:** Дозволяє кінцевому автомату (FSM) періодично запускати цикл очищення "завислих" (orphan) ордерів.
- **Причина вимкнення:** Очищення ордерів глобально делеговано модулю `OrderGuardian` (`guardian.unified=true`). Вимкнення локального циклу очищення FSM запобігає дублюванню логіки, зайвому навантаженню на API та потенційним гонкам (race conditions) при скасуванні ордерів.
- **Докази:** Документ `trading_passport.md`, код `apps/reference/domains/execution_position/fsm.py`.

### 2.4. `trading.execution.allow_trade_with_guardian_tidy_only`
- **Файл:** `config/aurora/trading.yaml`
- **Значення:** `false`
- **Логіка:** Шлюз (gate) для входу в позицію, який дозволяє відкривати нові ордери (`ENTRY`) тільки якщо нещодавно було підтверджено подію `EVT:SYMBOL_TIDY` від `OrderGuardian`.
- **Причина вимкнення:** Присутній значний ризик надмірного блокування торгівлі (over-blocking). У разі затримок або збоїв у роботі `guardian`, торгова система повністю б зупинила відкриття позицій. Гейт наразі вимкнено для збереження живучості (liveness).
- **Докази:** `trading_passport.md`, `apps/reference/domains/execution_position/event_handlers.py`.

### 2.5. `domains.decision_making.fail_closed_on_degraded_context`
- **Файл:** `config/aurora/domains.yaml`
- **Значення:** `false`
- **Логіка:** Глобальний перемикач безпеки (fail-closed). Якщо критичні змінні (як-от `price`, `ema_bias`, `obi`) відсутні у вхідних даних, модуль `DecisionMaking` примусово відкладає прийняття рішень (`DEFER`).
- **Причина вимкнення:** За замовчуванням вимкнено, щоб уникнути повного блокування торгівлі при частковій деградації даних, які можуть бути некритичними для певної угоди. Цей рівень суворості наразі визнаний зависоким для production-середовища.
- **Докази:** `domains_passport.md`, код `apps/reference/domains/decision_making/readiness_gates.py`.

### 2.6. `strategies.md_amr.execution.gtx_fallback_to_market`
- **Файл:** `config/aurora/strategies/llm_microstructure.yaml` (Вимкнено), `md_amr.yaml` (Формально увімкнено, фактично неактивно)
- **Логіка:** Якщо виставлення GTX (Post-Only) ордера лімітної ціни неодноразово відхиляється біржею, система автоматично переходить на MARKET ордер.
- **Причина вимкнення/Дрифт:** Для `llm_microstructure` це прямо вимкнено, бо наміри суворо зовнішні (система не може самовільно змінювати ліміт на маркет). Для інших стратегій (як `md_amr`) аудит виявив "дрифт": обробник `MDAMRHandler` лише логує перехід на маркет-ордер та скидає лічильник повторів, але фізично не виконує MARKET ордер.
- **Докази:** `config/docs/md_amr_strategy_passport.md`, `apps/reference/domains/decision_making/md_amr_handler.py`, `JOURNAL.md`.

### 2.7. `feature_engineering.macro_sync.anchor_update_from_ticks`
- **Файл:** `config/aurora/trading.yaml`
- **Значення:** `false`
- **Логіка:** Дозволяє оновлювати опорні макро-ціни (anchor prices, наприклад BTCUSDT) безпосередньо з тикових даних (ticks), не чекаючи на подію `EVT:ANCHOR_UPDATED`.
- **Причина вимкнення:** Використання тиків порушує подієву архітектуру системи та викликає ускладнення з live-versus-replay парністю (parity). Існування розбіжностей конфігів між `domains.yaml` та `trading.yaml` збільшує ризики, тому функція не активується.
- **Докази:** `BTC_CROSS_ASSET_INFLUENCE_AUDIT.md`, `tests/investigation/test_warmup_anchor_blockers.py`.

### 2.8. `domains.debug.disable_positions_stale_gate` та `disable_daily_loss_limit`
- **Файл:** `config/aurora/domains.yaml`
- **Значення:** `false`
- **Логіка:** Перемикачі для режиму розробки, які вимикають захисні механізми перевірки актуальності (stale gate) та денних лімітів збитків.
- **Причина вимкнення:** Строго заборонено увімкнення в production. Коментар визначає їх як `DEV/SHADOW ONLY... Never enable in live`. Вимкнені для гарантії безпеки капіталу.
- **Докази:** Коментарі у файлі `config/aurora/domains.yaml`.

### 2.9. `system.hawkes.bivariate`
- **Файл:** `config/aurora/system.yaml`
- **Значення:** `false`
- **Логіка:** Вмикає двовимірний (bivariate) режим для моделювання процесу Гоукса.
- **Причина вимкнення:** Поле наразі зарезервовано як метадані для майбутнього використання і ще не має імплементації у runtime логіці.
- **Докази:** Паспорт конфігурації `config/docs/system_passport.md`.

### 2.10. `mean_reversion.strategy.tp_to_mid` (Перевизначено на `false`)
- **Файл:** `config/aurora/strategies/mean_reversion.yaml`
- **Логіка:** Якщо `true`, тейк-профіт встановлюється на рівні середньої лінії смуг Боллінджера. Якщо `false` — націлюється на зовнішню смугу.
- **Причина вимкнення:** Не є глобально вимкненим, але встановлюється в `false` для специфічних активів (наприклад, DOGE). Для трендових і високо-волатильних активів націлювання на зовнішню смугу приносить більший прибуток, аніж вихід по середній лінії.
- **Докази:** Скрипти криміналістики `tools/forensics/doge_full_period_study.py`, тестові файли `test_task53_numeric_params_reach_runtime.py`.

### 2.11. `structural_stop_enabled`
- **Файл:** `config/aurora/domains.yaml`
- **Значення:** `false`
- **Логіка:** Дозволяє розрахунок динамічних стоп-лосів (structural stops) на основі алгоритмічної впевненості (pillar conviction) замість фіксованого множника ATR.
- **Причина вимкнення:** Вимкнено для збереження legacy-поведінки (використовується фіксований статичний множник `sl_k_atr = 1.5`), яка гарантує більш стабільні, передбачувані обмеження збитків до завершення валідації динамічної моделі.
- **Докази:** Клас EntryPlan `apps/reference/domains/decision_making/entry_plan.py`.

## 3. Висновки
Аналіз вимкнених конфігурацій (позначених як `false` або `disable`) у системі Aurora демонструє суворе дотримання архітектурних стандартів безпеки (Fail-Closed), ізоляції процесів та подієвої взаємодії:
1. **Ізоляція непідтверджених експериментів:** Нові потужні фічі, такі як Microstructure Veto та Bivariate Hawkes Process, відключені доти, доки не пройдуть повноцінну валідацію на live-даних.
2. **Мінімізація дублювання та конфліктів:** Функції FSM periodic cleanup відключені на користь глобального OrderGuardian.
3. **Відмова від over-blocking:** Надмірно суворі гейти безпеки (як-от Tidy Guardian Guard та Degraded Context) деактивовані, оскільки їх хибні спрацьовування можуть завдати більшої шкоди живому трейдингу, аніж потенційні проблеми, від яких вони захищають.
4. **Видалення "магічної" поведінки:** Автоматичні fallbacks, які порушують суворість ордерних намірів, деактивовані.

Цей звіт підтверджує, що усі вимкнені поля мають обґрунтовану технічну або архітектурну причину (згідно з принципами з `GEMINI.md`), підтверджену журналом аудиту.
