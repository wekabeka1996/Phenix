# Аналіз мікроструктурної фічі "Absorption" (Поглинання)

## 1. Концепція та мета фічі у фінансових реаліях
В контексті крипто-мікроструктури, **Absorption (Поглинання)** — це ринковий феномен, коли агресивний потік маркет-ордерів (наприклад, масові продажі) поглинається великою пасивною ліквідністю (limit ордери) без відповідного зсуву ціни. 

Наприклад: йде шквал маркет-селлів (TFI < 0), але ціна не падає, бо маркетмейкери або великі гравці підставляють ліміти (Iceberg orders / spoofing refill). Це сигнал зупинки тренду та часто передвісник гострого розвороту (short squeeze).

## 2. Реалізація у Phenix (Математика та Код)
Я проаналізував код в `apps/reference/domains/feature_engineering/calculation_engine.py` (функції `update_absorption` та `compute_absorption`). Наразі ця фіча в проєкті позначена як `Experimental (Default OFF)`.

### Поточна математична формула (Proxy mode)
Код рахує "proxy" (наближення) до поглинання за допомогою ковзних вікон об'ємів покупок та продажів:

```python
absorption = (sum_buy_vol - sum_sell_vol) / (sum_buy_vol + sum_sell_vol + eps)
```
*Де `sum_buy_vol` і `sum_sell_vol` - це суми об'ємів за вікно `absorption_proxy_window`.*

Після цього розрахунку додано **Dedup guard (захист від дублювання)**:
```python
corr = pearson_corr(proxy_vals[-10:], tfi_vals[-10:])
if abs(corr) > threshold:
    # MUTED: absorption too correlated with TFI
    return (neutral, False, "dedup_muted")
```
Тобто система намагається відрізнити absorption від звичайного Trade Flow Imbalance (TFI). Якщо вони занадто корелюють, фіча вважається "зламаною" (не дає нової інформації) і вимикається.

## 3. Критика реалізації (На скільки це коректно?)

**Оцінка коректності: 20-30% від справжнього поглинання.**

Поточна реалізація `proxy_value = (sum_buy - sum_sell) / (total)` математично є **просто згладженим TFI (Trade Flow Imbalance)** або V-Delta. Це **НЕ** є поглинанням у його мікроструктурному значенні.

### Чому ця формула хибна з точки зору ринку?
1. **Відсутність цінової дельти:** Справжнє поглинання *завжди* має ціновий контекст. Поглинання = "багато б'ють по ринку, але ціна не йде". Поточна формула дивиться ТІЛЬКИ на об'єми (`buy_vol` і `sell_vol`), повністю ігноруючи ціну або зміни стакану (OB).
2. **Сліпота до Limit ордерів:** Поглинання — це взаємодія агресивного маркет-потоку з пасивним ліміт-потоком. Але формула `(buy_vol - sell_vol)` містить лише маркет-потік. Ви не можете побачити айсберг-ордер, дивлячись тільки на стрічку принтів без прив'язки до OBI або ціни.
3. **Dedup Guard ламає власну логіку:** Розробник інтуїтивно зрозумів, що його формула — це просто TFI. Тому він додав Pearson correlation guard. Але оскільки формула *дійсно* є згладженим TFI, цей `dedup_guard` майже завжди буде спрацьовувати (кореляція буде високою), повертаючи `0.0`. Це пояснює, чому у логах вище значення absorption завжди було `0.0` (або `not_ready`).

## 4. Як правильно рахувати Absorption (Пропозиція нової Альфи)

Справжнє поглинання (CVD / Delta Divergence) має вимірювати розрив між агресією та результатом.

Ось 3 коректні математичні моделі поглинання, які використовуються у HFT (використовуючи змінні, які у вас вже є):

### Модель А: Price-Volume Divergence (Найпростіша)
```python
# TFI - це trade flow (агресія). Delta_price - це результат.
# Якщо є сильний потік продажів (TFI << 0), але ціна йде вгору або стоїть на місці (Delta_price >= 0) -> це BUY Absorption.

if tfi < -0.4 and delta_price >= 0:
    absorption = 1.0  # Бичаче поглинання (ліміти викуповують дно)
elif tfi > 0.4 and delta_price <= 0:
    absorption = -1.0 # Ведмеже поглинання (хтось роздає об'єми в маркети)
else:
    absorption = 0.0
```

### Модель B: OBI vs TFI Collision (Зіткнення лімітів і маркетів)
Поглинання — це коли OBI та TFI мають екстремальні, але **протилежні** знаки.
```python
# Маркети сильно продають (tfi < 0), але стакан сильно перекошений в біди (obi > 0.8)
# Хтось підставив величезну стіну, щоб поглинати продажі.

collision = obi * (-tfi) # (позитивне значення означає конфлікт)
if collision > 0.5:
    absorption_signal = sign(obi) * collision
```

### Модель C: Spread Efficiency (Токсичність потоку)
Якщо після масивного trade flow сппред (`spread_bps`) не розширюється і ціна не відступає, значить ліквідність миттєво поповнюється (refill). У вашому `calculation_engine` вже є `liquidity_kappa`. Можна рахувати поглинання як функцію від високого TFI при високій `liquidity_kappa`.

## Висновок
Поточна фіча `absorption` у `calculation_engine.py` (proxy mode) — це математичний тупик, оскільки вона просто дублює V-Delta/TFI і потім сама себе глушить через кореляційний фільтр (`dedup_guard`). Вона **не відображає** реального фінансового поглинання.

Оскільки вона і так вимкнена за замовчуванням (placeholder `0.0`), я рекомендую **переписати її логіку** на Модель А або B (комбінація `tfi` та `delta_price` або `obi`). Це дасть системі реальний, потужний сенсор розвороту ринку, який ідеально впишеться в існуючу архітектуру Aurora!
