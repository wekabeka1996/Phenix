Ось **чітка послідовність запуску всього мінімального стека для trading UI**.
Це саме той порядок, який тобі потрібен зараз.

**Що буде запущено**
1. `Phenix core runtime`
2. `Phenix core API` на `127.0.0.1:8000`
3. `Phenix shadow telemetry API` на `127.0.0.1:8443`
4. `Agent OS` UI/API на `127.0.0.1:3000`

`bridge-daemon` для trading terminal **не обов’язковий**.

---

## 0. Очистити старі процеси
Відкрий **PowerShell Terminal A** і виконай:

```powershell
Get-NetTCPConnection -LocalPort 8000,8443,3000 -State Listen -ErrorAction SilentlyContinue |
  Select-Object LocalPort, OwningProcess

Get-NetTCPConnection -LocalPort 8000,8443,3000 -State Listen -ErrorAction SilentlyContinue |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

Потім ще раз перевір:

```powershell
Get-NetTCPConnection -LocalPort 8000,8443,3000 -State Listen -ErrorAction SilentlyContinue
```

Якщо нічого не повернулося, порти чисті.

## 2. Запустити Phenix core API на 8000
Відкрий **PowerShell Terminal 2** і виконай:

```powershell
cd C:\Users\user\Music\Phenix
$env:TRADING_ENV="development"
.\.venv\Scripts\python.exe -m uvicorn apps.reference.api.main:app --host 127.0.0.1 --port 8000
```

Важливо:
- зараз **не використовуй `--reload`**, щоб не ловити старий route table;
- цей термінал теж **залишаєш відкритим**.

---

## 3. Запустити Phenix shadow telemetry API на 8443
Відкрий **PowerShell Terminal 3** і виконай:

```powershell
cd C:\Users\user\Music\Phenix
Remove-Item Env:SHADOW_TELEMETRY_BEARER_TOKEN -ErrorAction SilentlyContinue
Remove-Item Env:AURORA_SHADOW_TELEMETRY_BEARER_TOKEN -ErrorAction SilentlyContinue
.\.venv\Scripts\python.exe -m apps.reference.domains.shadow_telemetry.main --config-dir config/aurora --host 127.0.0.1 --port 8443 --log-level INFO
```

Чому без token:
- у тебе локальний loopback режим;
- для `127.0.0.1` bearer тепер не обов’язковий.

Цей термінал теж **залишаєш відкритим**.

## 5. Перевірити, що Phenix core API реально віддає trading routes
Відкрий **PowerShell Terminal 5** і виконай по черзі:

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8000/health
```

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8000/api/trading/positions/active
```

```powershell
Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:8000/api/trading/rejections/recent?limit=8"
```

```powershell
Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:8000/api/trading/market/overview?symbols=BTCUSDT,ETHUSDT,SOLUSDT,1000PEPEUSDT&tf_sec=300"
```

Правильний результат:
- **не** `404`
- або `200`
- або `503` якщо truth тимчасово недоступна

`404` тут означає, що ти все ще дивишся на старий процес.

## Якщо щось знову піде не так

### Якщо `8000 /health` працює, але `/api/trading/*` дає `404`
Ти запустив **старий core API процес**.
Зроби знову:

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen -ErrorAction SilentlyContinue |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

і потім **повторно** виконай крок 2.

### Якщо `8443` не піднімається
Подивись помилку прямо в **Terminal 3**.
Не запускай зараз через старий token-script, якщо тобі не потрібен bearer.

### Якщо `3000` піднявся, але terminal показує `unavailable`
Це вже означає, що `Agent OS` живий, але upstream truth surfaces у `Phenix` ще не дають коректної відповіді. Тоді треба дивитися результати кроків 5-7.
