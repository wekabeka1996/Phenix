# Run Integrity Audit: 20260312_132130 vs 20260313_031152

## 0. Executive Verdict

INVALID: Run B did not truly cover 2024-03-01 .. 2024-06-30.

Hard evidence shows that Run B resolved config and stdout both advertised 2024-06-30, but all factual execution artifacts stop in March: closed trades exist only in 2024-03, order-log events exist only in 2024-03, and stdout heartbeats end on 2024-03-31.

The strongest root cause is not overlay failure. The strongest root cause is missing Apr-Jun source parquet coverage, compounded by a runner/data-loader validation gap that allowed a March-only execution to be reported as Mar-Jun.

Primary cause confidence: high.

## 4. Data Coverage / Bar Count Plausibility

### Reported bar_count comparison

- Run A pipeline.bar_count = 54360
- Run B pipeline.bar_count = 54360

This is not plausible for a true Mar-Jun run.

Reason:

- Run A covers 31 calendar days.
- Run B claims to cover 122 calendar days.
- If the same symbol set and 5m basis were actually processed through June, Run B bar_count should be materially larger than Run A, not identical.
- A rough linear expectation is about 54360 x (122 / 31) = 213840 bars, not 54360.

## 5. Root Cause Assessment

Ranked assessment:

1. Something else: missing Apr-Jun processed source data, plus a coverage-validation gap in the runner/data loader. Confidence: high.
2. Runner bug. Confidence: medium. The runner or loader allowed a requested Mar-Jun run to complete and be labeled Mar-Jun without asserting that Apr-Jun data was actually present and processed.
3. Report formatting only. Confidence: low. This is ruled out because order logs, result trades, event coverage, heartbeat timestamps, and loaded parquet inventory are all March-only.
4. Overlay not applied. Confidence: low. This is ruled down because Run B resolved_config and stdout both clearly carry end_date=2024-06-30.
5. Config merge order issue. Confidence: low. Same reason: the final resolved config already contains the intended end_date.
6. Launcher bug. Confidence: low to medium. The launcher may have used a misleading stdout filename, but the actual run artifacts still show that the requested Mar-Jun range reached config resolution.

Most likely root cause statement:

- Primary: source data coverage ended at 2024-03.
- Secondary: the backtest runner/data loader failed to hard-stop or clearly fail the run when requested coverage exceeded available data.

## 6. Next Action

Do not treat Run B as a valid Mar-Jun benchmark.

What should happen next:

1. Inspect data availability and ingestion first, not overlay application.
2. Confirm that processed 5m parquet exists for 2024-04, 2024-05, and 2024-06 for the required symbols.
3. Only after Apr-Jun source data exists, rerun Run B.
4. Separately, inspect the runner/data-loader coverage validation so future runs fail fast when requested end_date exceeds actual loaded data coverage.
