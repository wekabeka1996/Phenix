# Mean Reversion Incident Research Report

## 1. Executive Summary
- **Incident Scope**: 5 consecutive SHORT intents generated by `mean_reversion` on DOGEUSDT between 10:35 and 11:45 UTC.
- **Action Taken**: 3 orders actually placed and filled (at 10:35, 10:50, and 11:45). 2 intents blocked by `FLIP_ORCHESTRATION` anti-pyramiding logic.
- **Rule Compliance**: `PROVEN YES`. All entries strictly adhered to the active `mean_reversion.yaml` configuration. The local `min_bb_width` of 0.005 allowed the entries.
- **Quant Assessment**: `BAD READ`. The strategy was fading an ultra-low volatility squeeze breakout (`bb_width` = 0.8%). Shorting a momentum expansion under the guise of "mean reversion" is a classic quant logic trap.
- **Execution Lifecycle Failure**: `CRITICAL DRIFT`. Stop-loss brackets were correctly dispatched to Binance Testnet as `STOP_MARKET` and filled on the exchange (evidenced by `PositionTracker` reporting 0). However, the execution FSM lost websocket sync or failed to process the `ORDER_UPDATED` event.
- **State Corruption**: Because `ManageFlowFSM` never reconciled the SL execution, it held the position open locally. But `DecisionMaking` read `Positions: 0` from the REST API polling layer, leading to a split-brain state.
- **Orphan / TTL Trigger**: Because `DecisionMaking` thought the portfolio was flat, it permitted a new SHORT at 10:50. This new position overwrote the FSM state for `DOGEUSDT`, implicitly orphaning the original `rid`. After exactly 3600 seconds (at 11:45:02), the orphaned `rid-a30db165502be7a4` was forcibly garbage-collected by `TradeLifecycleLogger` as `TTL_EXPIRED_3600s`.
- **Verdict**: The issue is a dual-layered failure: a weak quant filter in the strategy (allowing squeeze-fading) compounded by a split-brain reconciliation bug in the execution FSM upon receiving (or missing) websocket bracket fills.

## 6. Execution/Bracket Forensics
- **Who owned SL/TP**: `ManageFlowFSM` via Binance Testnet `STOP_MARKET` / `TAKE_PROFIT_MARKET`.
- **Where lifecycle broke**: `fsm_manage.py` relies on `TRADE_EXECUTED` or `ORDER_UPDATED` WebSocket messages to transition state and emit `POSITION_CLOSED`.
- **Reconciliation Gap**: There is zero evidence in `event_chain.log` that the WS message for `1000000024381566` was received. This created a split-brain state:
  - `TradeLifecycleLogger` & `ManageFlowFSM` thought the position was OPEN.
  - `PositionTracker` (polling REST) knew it was FLAT.
  - `DecisionMaking` used `PositionTracker`'s cache, allowing a new entry.
  - `ExecPosFSM` overwrote the tracking dictionary with the new trade, implicitly discarding the old one to the TTL watchdog.

## 7. Documentation Drift

- `LOW_VOLATILITY` is correctly mapped to `FLAT_LOW`.

## 9. Open Questions
1. Did Binance Testnet actually fail to send the WebSocket `ORDER_UPDATED` event for `STOP_MARKET` orders, or did our adapter drop it silently before it hit `event_chain.log`?
2. If `ExecPosFSM` receives a new `CMD:OPEN` for a symbol it is currently tracking, does it explicitly assert state, or does it silently overwrite the instance?

## 10. Decision-Ready Next Steps
- **P0**: Investigate `ExecPosFSM` and `ManageFlowFSM` behavior when a new `CMD:OPEN` is received while a position is internally marked `OPENED`. Implement a strict local reconciliation lock.
- **P0**: Investigate the WebSocket payload parsing in `BinanceAdapter` for `STOP_MARKET` fills on Testnet. Are we filtering them out?
- **P1**: Increase `min_bb_width` for `DOGEUSDT` in `mean_reversion.yaml` to at least `0.015` or `0.02` to prevent fading tight squeeze breakouts.
- **P2**: Implement a periodic state-reconciliation routine inside `ExecPosFSM` that cross-references its internal `sl_order_id` with `PositionTracker`'s REST API results. If REST says 0, and FSM says OPEN, FSM must force a transition to FLAT.
