# Якість коду та технічний борг Snapshot Scheduler

## 1. Hotspots та ризики
- **Synchronous File IO**: Запис знімків виконується синхронно (`f.write`). Якщо диск повільний або файл дуже великий, це затримує виконання всього циклу планувальника (але не впливає на торгівлю, бо це окремий потік).
- **Registry Reliance**: Метод `_get_domain_instance` покладається на атрибути об'єкта `FSM` або словник `domains`. Це робить зв'язок між компонентами дещо неявним.

## 2. Технічний борг (Debt Ledger)

| Елемент | Ризик | Доказ | Рекомендація | Пріоритет |
| :--- | :--- | :--- | :--- | :--- |
| **No Retention Policy** | Переповнення диску старими знімками. | `_save_snapshot` loop | Реалізувати автоматичне видалення знімків старших за 7 днів. | High |
| **JSON Performance** | CPU spikes при серіалізації великих станів. | `json.dump` usage | Використовувати `orjson` або `ujson` для швидкої роботи. | Medium |
| **No Integrity Check** | Запис пошкоджених файлів. | `_write_snapshot_file` | Розраховувати та зберігати контрольний хеш (MD5/SHA) для кожного файлу. | Low |

## 3. Рекомендації
- Впровадити асинхронний запис файлів через `aiofiles` (якщо домен буде переведено на `asyncio`).
- Додати стиснення (gzip) для знімків, щоб економити місце на диску.
