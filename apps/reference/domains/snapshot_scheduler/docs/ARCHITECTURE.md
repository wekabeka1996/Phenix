# Архітектура домену Snapshot Scheduler

## 1. Фоновий цикл (Scheduler Loop)
Домен працює в окремому фоновому потоці (`threading.Thread`), щоб не вносити затримок (latency) у головний торговий потік. Цикл використовує `threading.Event` для коректної обробки сигналу зупинки системи.

## 2. Динамічне виявлення доменів (Discovery)
Scheduler не має жорстких посилань на об'єкти доменів. Замість цього він використовує реєстр `FSM`:
1. Шукає домен за ім'ям у `fsm.domains`.
2. Перевіряє наявність методу `get_snapshot()`.
3. Якщо метод присутній — ініціює створення знімка.

## 3. Стратегія зберігання
Знімки зберігаються як окремі JSON-файли з використанням формату імені:
`{domain_name}_{YYYYMMDD_HHMMSS}.json`
Це забезпечує легку навігацію та можливість вибору точки відновлення (Point-in-time recovery).

## 4. Конфігурація
Параметри планувальника знаходяться в секції `ops.snapshots` конфігураційного файлу:
- `interval_sec`: Частота створення знімків.
- `snapshot_dir`: Шлях до папки на диску.
- `domains`: Список доменів, які підлягають обов'язковому архівуванню.
