# Архітектура домену Market Data

## 1. Патерн Hybrid Multi-Process Proxy
Для подолання обмежень GIL у Python та захисту ядра прийняття рішень від навантаження мережевого IO, домен розділено на два процеси:
- **Worker Process**: Повністю асинхронний (`asyncio`). Займається підтримкою WebSocket з'єднання, парсингом JSON та первинною агрегацією.
- **Main Process (Proxy)**: Приймає дані через `multiprocessing.Queue` та розсилає їх як FSM-події.

## 2. Ізоляція мережевих збоїв
Якщо Worker Process стикається з мережевими таймаутами або помилками Binance, він намагається перепідключитися самостійно. Головний процес отримує дані лише тоді, коли вони валідні.

## 3. Bar Aggregation Logic
`BarAggregator` працює за принципом Event Time:
- Бар закривається лише тоді, коли приходить тік із `ts >= next_open_time`.
- Це гарантує ідентичність результатів у рантаймі та бектесті.
- При виявленні розривів у часі (Gaps), домен інкрементує лічильник `gap_bars_skipped`.

## 4. Масштабованість (Sharding)
Архітектура дозволяє (хоча наразі не реалізовано у YAML) запускати декілька воркерів для різних груп символів, розподіляючи навантаження на кілька ядер CPU.
