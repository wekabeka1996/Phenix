# Якість коду та технічний борг Market Data

## 1. Hotspots та критичні ризики
- **Memory Leak у `WebSocketAggregator`**: Сет `seen_trade_ids` не має обмеження за розміром. При високій волатильності він може рости необмежено, що призведе до OOM (Out of Memory) вбивства воркера через 24-48 годин.
- **Connection Blackhole**: Відсутність `Read Timeout` в `aiohttp` сесії. Якщо Binance перестане слати дані, але триматиме сокет відкритим, воркер "зависне" назавжди.

## 2. Технічний борг (Debt Ledger)

| Елемент | Ризик | Доказ | Рекомендація | Пріоритет |
| :--- | :--- | :--- | :--- | :--- |
| **Zombie Logic** | Плутанина в точках входу. | `market_data_connector.py` | Повністю видалити старий конектор. | High |
| **Daemon Data Loss** | Втрата останніх секунд даних при шатдауні. | `daemon=True` у Proxy thread | Реалізувати graceful stop зі зливом черги IPC. | Medium |
| **Performance (BarAgg)** | O(N) операція при очищенні барів. | `pop(0)` у `BarAggregator` | Замінити на `collections.deque`. | Low |

## 3. Рекомендації по покращенню
- Впровадити **Reordering Buffer** на 50мс для обробки тіків, що прийшли не по порядку.
- Винести всі магічні числа (розміри логів, таймаути) у `system.yaml`.
- Додати автоматичний перезапуск Worker Process у разі його падіння (Watchdog).
