# Архітектура домену Regime Detector

## 1. Пріоритетна ієрархія моделей
Детектор застосовує моделі послідовно, де перша успішна детекція визначає режим:
1. **Volatility Model**: Якщо волатильність (ATR ratio) виходить за межі порогів — встановлюється `HIGH_VOLATILITY` або `LOW_VOLATILITY`.
2. **Mean Reversion Model**: Якщо ціна знаходиться у вузькому коридорі навколо SMA.
3. **SMA Trend Model**: Класичний перетин швидкої та повільної SMA.
4. **Fallback**: Якщо жодна модель не впевнена — `UNCERTAIN`.

## 2. Гістерезис та стабільність
Для уникнення "флапання" (частих перемикань режиму на межі значень) використовується механізм підтвердження:
- Новий режим стає "стабільним" (stable) лише після утримання протягом $N$ барів (`hysteresis_bars`).
- Події `EVT:REGIME_DETECTED` завжди транслюють стабільний режим.

## 3. Гейти якості даних (Data Quality Gates)
Домен реалізує суворий Fail-Closed:
- **Stale Gate**: Якщо дані затрималися довше ніж `bar_ttl_ms`, режим скидається в `UNCERTAIN`.
- **Liveness Heartbeat**: Домен емітує подію на кожному закритті бару, навіть якщо режим не змінився, щоб сигналізувати іншим системам про свою працездатність.

## 4. Volatility Slope Gate (Захист від шторму)
Спеціальна логіка, що відстежує швидкість зміни волатильності. Дозволяє раніше виходити з режиму `HIGH_VOLATILITY`, коли "шторм затихає", або навпаки — швидше блокувати торгівлю при різкому сплеску.
