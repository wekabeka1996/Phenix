# Архітектура домену Strategies

## 1. Протокольний підхід (Protocol-based)
Домен використовує Python Protocols (`runtime_checkable`) для забезпечення слабкого зв'язку (loose coupling):
- **`StrategyPlugin`**: Фабрика, що вміє створювати обробники за певним `strategy_id`.
- **`StrategyHandler`**: Стейтфул-об'єкт, що реалізує конкретну торгову логіку та підписується на шину FSM.

## 2. Процес бутстрапу (StrategyRuntime)
При старті системи `StrategyRuntime`:
1. Сканує `strategies_registry.assignments` у конфігурації.
2. Збирає унікальний набір `strategy_id`, які призначені хоча б одному символу.
3. Шукає відповідні плагіни у `StrategyPluginRegistry`.
4. Якщо плагін відсутній для призначеного ID — викидає `ConfigContractError` (Fail-closed).
5. Створює та реєструє обробники для всіх знайдених плагінів.

## 3. Реєстр дозволених плагінів (Allowlist)
Використання `StrategyPluginRegistry` діє як "білий список". Система не може випадково запустити невідому торгову логіку, якщо її плагін не був явно зареєстрований при ініціалізації.

## 4. Ізоляція обробників
Кожен створений `StrategyHandler` є автономним. Він отримує посилання на `FSMCore` та `AuroraConfig`, що дозволяє йому працювати як незалежному мікро-сервісу всередині одного процесу.
