# Якість коду та технічний борг Strategies

## 1. Hotspots та ризики
- **Config Reliance**: Метод `start()` використовує `getattr` для доступу до `strategies_registry`. Це робить запуск крихким у разі змін структури `AuroraConfig`, якщо вони не покриті тестами.
- **Single Instance Per Strategy**: Поточна реалізація створює один `StrategyHandler` на весь тип стратегії (напр. один хендлер для Aurora, що обробляє 10 символів). Це може призвести до "товстих" об'єктів та ускладнити масштабування.

## 2. Технічний борг (Debt Ledger)

| Елемент | Ризик | Доказ | Рекомендація | Пріоритет |
| :--- | :--- | :--- | :--- | :--- |
| **No Hot Reload** | Неможливість змінити стратегію без рестарту. | `start()` logic | Впровадити динамічну підписку на зміни конфігу. | Medium |
| **Silent Assignment Fail** | Пропуск некоректних типів даних у YAML. | `if not isinstance(ids, list): continue` | Додати сувору валідацію схеми призначень. | Low |

## 3. Рекомендації
- Перейти до моделі "Handler-per-Symbol" для кращої ізоляції та паралелізму.
- Впровадити автоматичне виявлення (auto-discovery) плагінів у папці `plugins/` через імпорт пакетів.
