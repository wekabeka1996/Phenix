# Алгоритми та математика домену Account Balance

## 1. Обробка чисел
Всі фінансові дані обробляються з використанням типу `decimal.Decimal` для запобігання помилкам з плаваючою крапкою, властивим `float`.

## 2. Логіка фільтрації

### Баланси (Assets)
При формуванні події `EVT:BALANCE_UPDATE_RECEIVED` застосовується фільтр:
$$balance > 0$$
Активи з нульовим балансом ігноруються для зменшення об'єму повідомлень.

### Позиції (Positions)
При формуванні події `EVT:ACCOUNT_UPDATE_RECEIVED` застосовується фільтр:
$$abs(position\_amount) > 0$$
(В коді реалізовано як `abs(float(amt)) > 0.0001` для відсікання мікро-залишків/пилу).

## 3. Розрахунок показників гаманця (Wallet Metrics)
Дані беруться безпосередньо з API Binance (`/fapi/v2/balance`), але важливо розуміти їх значення:
- **walletBalance**: Сума всіх поповнень/зняттів + реалізований PnL.
- **crossWalletBalance**: Баланс, доступний для забезпечення крос-маржинальних позицій.
- **crossUnPnl**: Нереалізований PnL по всіх крос-позиціях.

В коді `AccountConnector` ці значення витягуються конкретно для активу **USDT** як базової валюти розрахунків.

## 4. Визначення часу оновлення
Для `EVT:BALANCE_UPDATE_RECEIVED` час оновлення (`updateTime`) — це максимальний час серед усіх отриманих активів:
$$updateTime_{event} = \max(updateTime_{assets})$$
Для `EVT:ACCOUNT_UPDATE_RECEIVED` використовується поточний системний час моменту формування події.
