# Архітектура домену Account Balance

## 1. Внутрішня структура
Домен реалізований як автономний сервіс-конектор, що працює в окремому фоновому потоці (`threading.Thread`).

### Компоненти:
- **AccountConnector**: Клас, що ініціалізує `BinanceAdapter` на основі `trading_mode` (live/testnet).
- **Monitor Loop**: Нескінченний цикл у фоновому потоці, який використовує `asyncio` для асинхронних викликів адаптера всередині синхронного потоку.

## 2. Життєвий цикл (Lifecycle)
1. **Ініціалізація**: Отримання конфігурації, перевірка API ключів, створення адаптера.
2. **Start**: Запуск `_monitor_loop` у фоновому потоці.
3. **Running**: Послідовне виконання запитів до `/fapi/v2/balance` та `/fapi/v2/positionRisk`.
4. **Stop**: Сигнал зупинки циклу, закриття сесії `BinanceAdapter`, завершення потоку.

## 3. Конфігурація
Домен використовує `AuroraConfig` зі наступними ключовими параметрами:
- `account_observer.poll_interval`: Час очікування між ітераціями (зазвичай 30 секунд).
- `trading_mode`: Вибір між `live` та `testnet`/`hybrid`.
- `binance_api`: Набір ключів та URL-адрес для відповідного режиму.

## 4. Обробка помилок (Fail-closed)
- Якщо API ключі відсутні або некоректні — викидається `ConfigContractError` при старті.
- Якщо запит до API завершується помилкою (Network/Timeout) — помилка логується, але цикл продовжується (retry на наступній ітерації).
- Дані про баланс зберігаються в пам'яті (`self._latest_balance_data`) для забезпечення контексту при оновленні позицій.
