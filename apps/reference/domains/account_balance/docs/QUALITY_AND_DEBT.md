# Якість коду та технічний борг домену Account Balance

## 1. Hotspots та складність
- **Синхронний потік для асинхронних операцій**: Використання `threading.Thread` з внутрішнім `asyncio.run` або власним циклом подій є "клеєм" між старим синхронним кодом та асинхронним `BinanceAdapter`. Це ускладнює діагностику при зупинці системи.
- **Dependency on USDT**: Логіка `_emit_positions_update` жорстко прив'язана до наявності `USDT` у відповіді балансу для заповнення загальних метрик гаманця.

## 2. Технічний борг (Debt Ledger)

| Елемент | Ризик | Доказ (Pointer) | Рекомендація | Пріоритет |
|---------|-------|-----------------|--------------|-----------|
| **Polling (Polling over WebSockets)** | Затримка даних до 30с. | `self.update_interval` у `_monitor_loop` | Впровадити WebSocket User Data Stream для миттєвих оновлень. | High |
| **Blocking logic in Thread** | При зависанні мережевого запиту потік блокується. | `loop.run_until_complete` у `_monitor_loop` | Перейти на повну асинхронну архітектуру (без окремих потоків). | Medium |
| **Manual Field Mapping** | Велика кількість ручного мапінгу полів (`positionAmt` vs `position_amount`). | `_emit_positions_update` | Використовувати Pydantic моделі для мапінгу відповідей API. | Low |

## 3. Мертвий код (Dead Code)
- Метод `_dget` дублює стандартну поведінку `dict.get(key, default)`, але введений через специфічну політику (TASK25). Хоча він використовується, це створює нестандартний патерн.

## 4. Ризики
- **Rate Limits**: Поточна реалізація не має інтелектуальної черги запитів. Якщо інтервал опитування буде занадто малим, API Binance заблокує IP.
