# Архітектура домену Position Tracking

## 1. Цілісність даних (Truth Domain Hardening)
Домен працює за принципом "Truth-First":
- При старті система не емітує "порожній" портфель.
- Стан відновлюється або з останнього знімка (Snapshot) + реплей WAL, або після першої повної синхронізації з акаунтом біржі (`ACCOUNT_UPDATE`).

## 2. Механізм WAL (Write-Ahead Log)
Кожна подія, що змінює стан (виконана угода), спочатку записується у WAL. Тільки після підтвердження запису на диск (`wal.append`) подія обробляється логікою. Це гарантує можливість повного відновлення портфеля після збою.

## 3. Синхронізація з біржею (Account Reconciliation)
Окрім відстеження угод, домен постійно звіряє свій внутрішній стан з `EVT:ACCOUNT_UPDATE_RECEIVED`.
- Якщо виявлено позицію на біржі, якої немає в пам'яті (або навпаки), домен інкрементує метрику `manual_intervention_detected` та емітує алерти.
- Внутрішній стан примусово оновлюється до "біржової реальності".

## 4. Обробка маржі та плеча
Домен розраховує використання маржі для кожного символу, використовуючи дані про плече (leverage) з `instruments.yaml`. Це необхідно для роботи `ExposureGuard` у домені виконання.
