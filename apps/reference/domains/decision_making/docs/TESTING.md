# Тестування домену Decision Making

## 1. Стратегія тестування
Через високу складність домену використовується багаторівневе тестування:
1. **Unit Tests**: Тестування чистих математичних ядер (`EntryPlan`, `ScoringKernel`) на детермінованих входах.
2. **Component Tests**: Перевірка гейтів ризику та QoS без підключення до біржі.
3. **Integration Tests**: Симуляція повного циклу: `CMD:PROCESS_STRATEGY` -> `DecisionMaking` -> `EVT:TRADE_INTENT_PROPOSED`.

## 2. Ключові сценарії
- **Flip Orchestration**: Перевірка послідовності ордерів при зміні напрямку Long -> Short.
- **QoS Rate Limiting**: Перевірка блокування наміру при перевищенні ліміту 6 ордерів/хв.
- **Fail-Closed Verification**: Симуляція відсутності ціни, ліквідності або ліміту ризику — перевірка, що намір НЕ створюється.
- **Rounding & Precision**: Перевірка відповідності `qty` кроку лота біржі (step size).

## 3. Метрики покриття
- **Критичні гейти**: 95%
- **Сайзинг та Математика**: 100%
- **Обробка помилок конфігу**: 80%

## 4. Прогалини (Gaps)
- Недостатньо тестів на стан гонитви (race conditions) між швидкими оновленнями портфеля та генерацією сигналів.
- Відсутні тести на довгострокове накопичення похибки в `_side_intent_window`.
