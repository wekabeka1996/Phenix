# Якість коду та технічний борг Regime Allowlist

## 1. Hotspots та ризики
- **Hardcoded Regime List**: Список режимів у `contract.py` захардкоджений. Якщо додати новий режим у `regime_detector`, необхідно вручну оновити `regime_allowlist`, інакше система видаватиме `WARNING`.
- **Strategy Mapping Complexity**: Логіка перевірки сумісності (напр. що MR потребує FLAT) прописана безпосередньо в коді функцій. При додаванні 3-ї та 4-ї стратегії це перетвориться на громіздкий `if-elif`.

## 2. Технічний борг (Debt Ledger)

| Елемент | Ризик | Доказ | Рекомендація | Пріоритет |
| :--- | :--- | :--- | :--- | :--- |
| **Manual Sync** | Розбіжність з детектором режимів. | `ALL_REGIMES` set | Винести назви режимів у спільний `Shared Enum`. | Medium |
| **Implicit MR logic** | Непрозорість правил сумісності. | `is_mr_enabled_but_blocked` | Перейти до таблиці відповідності стратегія-режим у конфігу. | Low |

## 3. Рекомендації
- Створити спільний для всієї системи Enum зі списком режимів.
- Винести матрицю сумісності стратегій та режимів у YAML файл, щоб зробити систему більш гнучкою.
