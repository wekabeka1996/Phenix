# Архітектура домену Feature Engineering

## 1. Модель розділеного стану (Hot/Cold State)
Для забезпечення продуктивності в реальному часі домен використовує два рівні стану для кожного символу:
- **HotState**: Оновлюється на кожному тіку. Містить ціну, EMA, буфер об'єму. Орієнтований на мілісекундні затримки.
- **ColdState**: Оновлюється рідше (напр. раз на хвилину). Містить Funding Rate, Open Interest та макро-параметри.

## 2. Потокова обробка (Tick-based Pipeline)
Процес розрахунку ознак ініціюється подією `EVT:MARKET_TICK_RECEIVED`:
1. **Update State**: Тік записується в `HotState`.
2. **Resample**: Якщо час бару завершився, `BarResampler` закриває свічку.
3. **Calculate**: `CalculationEngine` обчислює вектори:
   - `flow`: OBI, TFI, Imbalance.
   - `trend`: Delta Price, EMA Bias.
   - `volatility`: Volatility State.
4. **Emit**: Результати упаковуються в `EVT:FEATURES_CALCULATED`.

## 3. Принципи обчислень
- **O(1) Complexity**: Домен уникає циклів по списках угод на кожному тіку. Використовуються агрегати, що оновлюються інкрементно (напр. Алгоритм Уелфорда для середнього та дисперсії).
- **Additive-only Versioning**: Нові ознаки додаються як нові ключі в словник, не змінюючи структуру існуючих даних для зворотної сумісності.

## 4. Конфігурація (Features SSOT)
Всі параметри індикаторів (періоди EMA, вікна волатильності) винесені в `config/aurora/features.yaml`. Використовується сувора валідація через Pydantic.
