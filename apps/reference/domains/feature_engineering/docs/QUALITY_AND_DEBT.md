# Якість коду та технічний борг Feature Engineering

## 1. Hotspots та ризики цілісності
- **Magic Timestamps**: Код використовує евристику `if ts < 1e12` для визначення одиниць часу (секунди vs мілісекунди). Це може призвести до спотворення даних при роботі з дуже старими архівами або специфічними біржами.
- **Silent Fallbacks**: Широке використання блоків `try/except Exception`, які повертають `neutral_value` (0.0). Це приховує математичні помилки та деградацію даних, ускладнюючи діагностику в рантаймі.

## 2. Технічний борг (Debt Ledger)

| Елемент | Ризик | Доказ | Рекомендація | Пріоритет |
| :--- | :--- | :--- | :--- | :--- |
| **Causality Hacks** | Порушення порядку подій. | `ts - 1ms` у синтетичних тіках | Використовувати детерміновану чергу подій без маніпуляції часом. | High |
| **Performance (Winsorize)** | $O(N \log N)$ на кожному тіку. | `sorted(data)` у `CalculationEngine` | Перейти на `numpy` або інкрементальні перцентилі. | Medium |
| **Shadow Config** | Непрозорість логіки. | Хардкод ваг у `MeanReversion1mStrategy` | Перенести всі коефіцієнти в `features.yaml`. | Medium |
| **Wallclock Leaks** | Недетермінованість бектесту. | `time.time()` у серцебитті | Використовувати виключно ін'єктований `Clock`. | High |

## 3. Мертвий код
- Метод `on_tick` у `mean_reversion_strategy.py` дублює логіку `on_bar`. Рекомендується до повного видалення для запобігання "Split-Brain" ефекту.

## 4. Рекомендації

- Замінити мовчазні повернення `0.0` на механізм `SanityResult` (Ok/Warn/Fail).
