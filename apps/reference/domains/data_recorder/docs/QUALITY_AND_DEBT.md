# Якість коду та технічний борг Data Recorder

## 1. Ризики та Hotspots
- **Schema Drift**: Якщо набір ознак у `EVT:FEATURES_CALCULATED` зміниться під час роботи (наприклад, додасться нова ознака), CSV файл матиме рядки з різною кількістю колонок, що зламає парсери (напр. Pandas).
- **Linear Search in Buffer**: У методі `on_regime` пошук по буферу виконується лінійно (`for key in list(self._buffer.keys())`). При великій кількості символів та високій частоті це може споживати багато CPU.

## 2. Технічний борг (Debt Ledger)

| Елемент | Ризик | Доказ | Рекомендація | Пріоритет |
|---------|-------|-------|--------------|-----------|
| **Linear Lookup** | CPU spikes при 50+ символах. | `on_regime` loop | Використовувати вторинний індекс `(symbol, ts) -> key`. | Medium |
| **CSV Format** | Відсутність типів даних, великий об'єм. | `_append_to_file` | Використовувати Parquet для компактності та збереження типів. | High |
| **Memory Buffer** | Втрата даних при раптовому вимкненні. | `_buffer` у пам'яті | Впровадити WAL (Write Ahead Log) або частіше скидання. | Low |

## 3. Рекомендації
- Додати валідацію стабільності схеми перед записом.
- Реалізувати підтримку стиснення (gzip) для CSV файлів.
