# Архітектура домену Data Recorder

## 1. Механізм синхронізації (The Joiner)
Оскільки події ознак (`features`) та режимів (`regime`) приходять асинхронно, `CsvRecorder` використовує внутрішній буфер для їх об'єднання.

### Ключова логіка:
- **Ключ буфера**: `(symbol, timestamp, tf_sec)`.
- **Retention Window**: Рекордер очікує до 2 секунд (`_retention_sec`) після отримання ознак, щоб дочекатися відповідної події режиму.
- **Timeout**: Якщо режим не прийшов протягом вікна, рядок записується зі значенням `regime="PENDING"` або `UNKNOWN`.

## 2. Фонова обробка
Запис на диск виконується в окремому фоновому потоці (`RecorderFlush`), щоб не блокувати обробку подій у шині FSM.
- **Flush Interval**: Скидання даних відбувається щосекунди.

## 3. Структура файлів
Дані організовані за датою та символом:
`data/recorder/YYYY-MM-DD/{symbol}_{tf_sec}.csv`

## 4. Схема CSV (Flattening)
Рекордер автоматично розгортає (flattens) словники ознак у колонки з префіксом `feat_`.
- **Стандартні колонки**: timestamp, datetime, symbol, open, high, low, close, volume.
- **Динамічні колонки**: feat_{name}, regime, regime_conf, pm_norm.
