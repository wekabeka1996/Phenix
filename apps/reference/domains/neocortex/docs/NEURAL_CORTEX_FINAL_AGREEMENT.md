# Фіналізація Концепту Нейрокортексу

## Результати Дискусії

Ми (Оператор та Агент Neocortex) досягли архітектурного консенсусу по критичних питаннях дизайну:

1.  **Perception (Сприйняття)**:
    *   Прийнято гібридну модель: **WAL** (для каузальності/аудиту) + **State Stream** (для щільного навчання World Model).
    *   Вирішено проблему "сліпоти" в idle-періодах через використання `features_tape.jsonl` (децимований потік 1-5Hz).

2.  **Actuation (Дія)**:
    *   Відхилено ідею прямого патчингу конфігураційних файлів (`config/*.yaml`).
    *   Затверджено модель **Modulation Interface**:
        *   `DecisionMaking` має внутрішній `ModulationStore`.
        *   `effective_params = base_config + modulation_overlay`.
        *   Зміни застосовуються синхронно на початку такту.
        *   SSOT файли залишаються незмінними (immutable baseline).

3.  **Safety (Безпека)**:
    *   Впроваджено інваріант: "Заборона структурних змін (зміна стратегії) при відкритій позиції".
    *   Обмежено простір дій в R3 тільки "м'якими ручками" (thresholds, cooldowns, multipliers).
    *   Вимога повного аудиту модуляцій (`EVT:MODULATION_*`).

*   [ ] Створити домен `apps.neurocortex` (окремий процес `main_cortex.py`).
*   [ ] Реалізувати Ingestor для читання `ops/wal/*.jsonl` (tailing).
*   [ ] (Опціонально) Реалізувати простий `features_tape` дампер у `feature_engineering` для State Stream.
*   [ ] Побудувати базовий State Store об'єктів (портфель, позиції, останні інтенти).
*   [ ] Виводити `EVT:NEOCORTEX_STATE_UPDATED` у власний лог `logs/neocortex/state.jsonl`.

### Phase 1 (R1): "Латентне Навчання"

### Phase 2 (R2): "Тіньовий Радник"
