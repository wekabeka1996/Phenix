# План Експерименту 2.2: Ізоляція пам'яті LSTM та Межі Епізодів (Causal Stream Poisoning)

## Мета
Емпірично довести наявність критичного багу попередніх версій (cross-asset memory poisoning) та показати, що архітектура "мережі як чистої функції" з управлінням словником станів з боку Actor-а вирішує проблему змішування причинно-наслідкових потоків.

## Вхідні Дані (Симуляція потоків)
- 2 інструменти: **BTCUSDT** та **ETHUSDT**.
- **BTCUSDT** отримує аномальний ринковий шок (сигнал `+100.0`).
- **ETHUSDT** залишається в абсолютному флеті (сигнал `0.0`).

## Моделі для порівняння
Для симуляції рекурентної пам'яті (LSTM) використовується проста функція акумуляції: $H_{new} = 0.5 \cdot H_{old} + Input$.
1. **Buggy_Actor (Shared State):** Використовує один глобальний прихований стан $H$ для обох активів (так, як це було зроблено в старій `ppo_library_v2`).
2. **Fixed_Actor (Isolated State):** Використовує словник `hidden_states = {"BTCUSDT": 0.0, "ETHUSDT": 0.0}`.
3. **Reset_Actor (Episode Boundaries):** Те саме, що і Fixed, але коли система генерує сигнал `done=True` (кінець епізоду), стан активу примусово обнуляється.

## Алгоритм (Actor Memory Management)
1. Симулюємо ітерацію: приходить сигнал по BTC, потім сигнал по ETH.
2. Проганяємо через обох акторів.
3. Заміряємо вихідний стан (Output/Memory) для ETHUSDT після того, як стався шок на BTCUSDT.

## Критерії Успіху
1. **Перевірка Отруєння:** `Buggy_Actor` покаже, що пам'ять для ETH різко підскочила через подію на BTC (Causal Poisoning).
2. **Перевірка Ізоляції:** `Fixed_Actor` покаже, що пам'ять для ETH залишилась рівною `0.0` (чиста).
3. **Перевірка Епізодів:** `Reset_Actor` покаже, що після події `done=True`, пам'ять скидається, запобігаючи нескінченному накопиченню минулого (Catastrophic Memory Leak).
