## УРОК 3.0 — Загальна pipeline компіляції

**Теза:** компіляція — це **ланцюжок перетворень**, а не “одна команда gcc”.

**Терміни:** source code, compiler, assembler, object file, linker, executable.

**Практика:**

* Намалювати повний pipeline з артефактами на кожному кроці
* Пояснити, що є “вхід” і “вихід” кожного етапу

**Міні-тест:**

* “На якому етапі код стає машинним?”

---

## УРОК 3.1 — Compiler: від мови до інструкцій

**Теза:** компілятор не “розуміє сенс”, він **перетворює структури**.

**Терміни:** front-end, back-end, IR (intermediate representation), optimization.

**Практика:**

* Пояснити різницю між front-end і back-end
* Приклад: чому один і той самий C-код можна скомпілювати під різні ISA

**Міні-тест:**

* “Чому компілятор не залежить від конкретного CPU напряму?”

---

## УРОК 3.2 — Assembler і машинний код

**Теза:** асемблер — це **прямий перекладач** між текстом і бітами.

**Терміни:** assembly, mnemonic, opcode, instruction encoding.

**Практика:**

* Порівняти: C-рядок → асемблер → машинний код (концептуально)
* Пояснити, чому асемблер майже не “думає”

**Міні-тест:**

* “Що станеться, якщо змінити одну інструкцію в asm?”

---

## УРОК 3.3 — Object file: чому не одразу executable

**Теза:** object file — це **незавершена програма**.

**Терміни:** object file, symbol, relocation, section.

**Практика:**

* Пояснити, чому великий проєкт не компілюється “в один файл”
* Намалювати object file як контейнер з секціями

**Міні-тест:**

* “Чому object file не можна запустити?”

---

## УРОК 3.4 — Символи і залежності

**Теза:** символи — це **імена, які ще не мають адрес**.

**Терміни:** symbol table, defined/undefined symbol, external linkage.

**Практика:**

* Пояснити, як функція з одного файлу використовується в іншому
* Приклад “undefined reference” (концептуально)

**Міні-тест:**

* “Чому компілятор не може сам вирішити всі посилання?”

---

## УРОК 3.5 — Linker: зшивання в одне ціле

**Теза:** linker — це **архітектор адресного простору програми**.

**Терміни:** linker, relocation, address space, static vs dynamic linking.

**Практика:**

* Намалювати, як кілька object files стають одним executable
* Пояснити роль relocation

**Міні-тест:**

* “Чим linker відрізняється від компілятора принципово?”

---

## УРОК 3.6 — ELF як структура

**Теза:** ELF — це **опис того, як завантажити програму**, а не “просто файл”.

**Терміни:** ELF header, program header, section header, segment.

**Практика:**

* Намалювати структуру ELF (блок-схема)
* Пояснити різницю між section і segment

**Міні-тест:**

* “Чому loader дивиться на segments, а не sections?”

---

## УРОК 3.7 — Loader: народження процесу

**Теза:** loader створює **процес**, а не “запускає файл”.

**Терміни:** loader, virtual address space, mapping, entry point.

**Практика:**

* Покроково описати запуск програми:

  1. створення адресного простору
  2. mapping сегментів
  3. ініціалізація стеку
  4. jump до entry point

**Міні-тест:**

* “Чому без loader немає процесу?”

---

## УРОК 3.8 — Памʼять процесу (оглядово, без глибини ОС)

**Теза:** процес — це **структурований віртуальний простір памʼяті**.

**Терміни:** text, data, bss, heap, stack.

**Практика:**

* Намалювати memory layout процесу
* Пояснити, де що лежить і чому

**Міні-тест:**

* “Чому стек і heap ростуть у різні боки?”

---

## УРОК 3.9 — Статичне vs динамічне лінкування

**Теза:** спосіб лінкування — це **інженерний компроміс**.

**Терміни:** static linking, dynamic linking, shared library.

**Практика:**

* Порівняти плюси/мінуси static vs dynamic
* Пояснити, де виникають runtime-помилки

**Міні-тест:**

* “Чому програма може не стартувати, хоча скомпілювалась?”

---

## УРОК 3.10 — Де і як виникають помилки

**Теза:** більшість “дивних багів” — це **наслідок pipeline**, а не логіки коду.

**Терміни:** compile-time error, link-time error, load-time error, runtime error.

**Практика:**

* Класифікувати 5 типових помилок по стадіях
* Пояснити, чому вони виникають саме там

**Міні-тест:**

* “На якій стадії ловити конкретний баг?”

## Appendix E3 — Compiler → assembler → object → linker → ELF → loader (Етап 3)

**Мільстоун:** *“ELF autopsy”*

* Зібрати маленьку програму з 2–3 файлів і:

  * пояснити, чому з’являються undefined symbols
  * показати, що робить linker (на рівні relocation/символів)
  * описати, як loader мапить сегменти (text/data/heap/stack)

**Інструменти:**

* `readelf`, `objdump`, `nm`, `ldd` (мінімум: вміти прочитати вивід і пояснити).

**Історична причина:**

* Великі системи потребували **модульності** (object files) і **пізнього зв’язування** (linking/loading), інакше збірка/перевикористання стає неможливим.

**Зарахування:**

* Ти чітко розрізняєш: compile-time vs link-time vs load-time vs runtime помилки (і наводиш приклади).
